# 文明OS

## 节点7：项目分层与时空坐标结构


【当前阶段·已实现】

**主结构（项目层级分解）：**

```
宇宙觉醒
 └─ 文明阶段
     └─ 技术领域
         └─ 项目
             └─ 子任务
                 └─ 步骤
```

**时空坐标附加：** 每个节点附带时空坐标（时间范围 + 抽象空间范围），坐标允许重叠。

**空间描述规范：** 使用范围性描述（如"太阳系内""银河系悬臂""可观测宇宙"），不使用具体地点坐标。

**层级截断规则：** 顶层固定保持宇宙觉醒级抽象水平；下层按需截断或扩展细节。

---

**节点标准数据格式（JSON Schema 规范）：**

每个节点的结构化表示应包含以下字段：

```json
{
  "id": "string (uuid)",
  "layer": "integer (0=顶层宇宙觉醒, 数字越大越底层)",
  "parent_id": "string|null (上层节点id, 根节点为null)",
  "title": "string (节点名称)",
  "description": "string (~100 token文本描述)",
  "time_range": {
    "start_year": "float",
    "end_year": "float"
  },
  "space_scope": "string (抽象空间范围描述, 如'太阳系内', 非具体地点, 允许重叠)",
  "status": "enum: placeholder | draft | verified | outdated",
  "last_updated": "string (ISO-8601日期)",
  "model_tier": "enum: 1B | 3B | 7B | 14B | 32B | 125B | cluster",
  "children_count": "integer",
  "cross_refs": "array[string] (关联节点id列表, 节点间互引)",
  "confidence": "float (0.0~1.0)",
  "data_source": "enum: inference | literature | measured",
  "iteration_version": "string (当前迭代版本号)"
}
```

**字段说明：**

| 字段 | 用途 |
|------|------|
| `id` | 全局唯一标识，用于 `parent_id` 和 `cross_refs` 的引用锚点 |
| `layer` | 编码层级深度，支持按层过滤与截断渲染 |
| `parent_id` | 构建树形结构；根节点（宇宙觉醒）为 `null` |
| `description` | 约100 token的摘要，供上层节点聚合展示 |
| `time_range` | 浮点年份，支持跨尺度（如 13.8e9 ~ 0 表示宇宙史） |
| `space_scope` | 范围性描述，允许重叠，不绑定具体坐标 |
| `status` | 生命周期状态：placeholder→draft→verified→outdated |
| `model_tier` | 处理该节点推荐的模型层级，指导计算资源分配 |
| `cross_refs` | 非树形关联（如"量子计算"节点引用"材料科学"节点） |
| `confidence` | 反映 `data_source` 与推理链的可靠程度 |
| `data_source` | 区分知识来源，影响 `confidence` 的合理上限 |

**实施阶段说明：** 当前纯文本阶段此 schema 作为设计规范文档保留；后续结构化阶段将每个节点文件的元数据区按此格式实现。

> ### 子节点07-01：节点schema 14字段详细说明
> id（uuid）：唯一标识，生成规则：时间戳+随机串
> layer（int）：层级，0=顶层宇宙觉醒，数字越大越底层越具体
> parent_id（uuid/null）：上层节点id，根节点为null
> title（string）：节点名称，建议30字以内
> description（~100 token）：核心内容摘要，供AI快速理解节点定位
> time_range（{start_year,end_year}）：float型年份，负数=公元前，科学计数法表示远期
> space_scope（string）：抽象范围，如"太阳系内""地球陆地""东亚地区"，允许重叠
> status：placeholder（占位待填）/draft（草稿）/verified（已验证）/outdated（需更新）
> last_updated（ISO-8601）：最近一次内容变更日期
> model_tier：1B/3B/7B/14B/32B/125B/cluster，推荐处理此节点的模型层级
> children_count（int）：直接子节点数量
> cross_refs（[uuid]）：显式关联节点列表，用于依赖图传播
> confidence（0.0~1.0）：内容置信度，推理=0.5~0.7，文献支撑=0.7~0.9，实测=0.9+
> data_source：inference/literature/measured，主要来源类型
> iteration_version（int）：该节点经历的迭代轮次计数
> 【当前阶段】纯文本实施：只维护title+description+time_range（手动，其余字段为规范备存）

> ### 子节点07-02：从宇宙觉醒到可执行步骤的典型拆解示例
> 以"清洁能源系统"为例展示完整拆解链：
> 层0（宇宙觉醒）：宇宙物质-能量最优利用
> 层1（文明阶段）：地球文明能源系统优化，时间范围2000~2100年
> 层2（技术领域）：太阳能技术路线，空间范围：全球陆地+海面
> 层3（具体项目）：钙钛矿太阳能电池效率提升，置信度0.85，来源：文献
> 层4（子任务）：稳定性问题攻关，status：draft
> 层5（可执行步骤）：合成新型封装材料，model_tier：7B，时间范围：2025~2027年
> 粒度控制原则：顶层=方向性（不可执行），底层=可执行（有明确主体/时间/方法）
>
> ### 子节点07-03：空间坐标系设计原则与重叠处理
> 为何用抽象范围而非具体地点：避免坐标系精度与内容精度不匹配，
> 减少因政治地理变化导致的节点失效
> 允许重叠的逻辑：不同维度的项目可以发生在同一空间，互不冲突
> 重叠时的处理：通过cross_refs建立空间关联，不合并节点
> 空间粒度匹配原则：同层级节点应有相似的时空粒度（不能同层一个是"宇宙"一个是"某市"）
