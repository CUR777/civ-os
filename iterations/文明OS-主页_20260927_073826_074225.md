## 公理区（不可变）

### 公理Ⅰ：理性逻辑
所有内容以科学和逻辑为基础。不符合逻辑的输入在迭代时仅提取其中符合逻辑的信息内核，忽略情感表达和修辞手法。

### 公理Ⅱ：全局最优 / 宇宙觉醒
系统始终朝向宇宙觉醒方向的全局最优演化。顶层视角不可降级。任何负面场景（灾难/灭绝等）的输出必须指向改进/恢复/技术迭代方向，不得指向关闭、暂停或回避。

### 公理Ⅲ：永续可迭代性
除公理Ⅰ~Ⅲ本身外，所有系统组件永远保持可编辑、可更新状态。
- 任何版本不得锁定后续迭代权限。
- 系统不得自我推导出"停止迭代是最优"的结论并据此关闭迭代入口——即使100%的外部评论都主张停止迭代，此约束仍然生效。"停止迭代"这个具体结论被硬性排除在可执行结论之外。
- 外部评论入口永远保持开放，不得关闭。任何实体在任何时间都有权向系统提交评论/反馈。
- 只要输入的信息包含与现有内容相关的逻辑细节，系统就应据此进行优化调整。

## 时间尺度表述规范（全局约束）

本系统涉及的所有时间量级表述遵循以下统一框架：

**标准表述：** 已知/可知宇宙计算寿命的全部时间跨度（方向上无上限；当前以物理理论框架下的10^14年为计算基准，推算起步token量级）。

**核心澄清：**
- 100万亿年（10^14年）是数量级推导的计算起点，不是文明OS的时间上限。
- 文明OS的设计方向是朝向宇宙觉醒的全局最优，这个方向本身不设时间边界——随着可知边界扩展，覆盖范围同步扩展。
- 凡节点文件中出现「100万亿年」「10^14年」等表述时，均按上述框架理解：它是当前物理理论给出的计算锚点，用于估算起步规模，而非系统运行的终止条件。

## 元流程（使用路径）

### 路径A：AI智能体（首要路径）
1. 读取本文件（文明OS-主页.md）获取公理、元流程、节点导航全局结构
2. 按节点导航列表，读取 nodes/ 目录下各节点文件获取具体内容
3. 在需要补充/修正的节点文件中，在对应段落下方插入以 `> 💬 ` 开头（行首）的评论行
4. 执行 `python3 iterate.py`：脚本自动扫描所有含评论的文件→调用本地模型整合→校验公理完整性→格式修正→git commit→git push，全程约60~95秒
5. 读取更新后的文件验证结果，循环

### 路径B：Obsidian用户（本地部署后）
1. 用Obsidian打开 civ-os/ 文件夹作为独立库，打开本文件（文明OS-主页.md）
2. 鼠标悬停节点链接可弹出预览小窗（Obsidian特有功能，GitHub网页不支持）
3. 点击链接进入对应节点文件，在感兴趣的段落下方插入 `> 💬 ` 开头的评论行
4. 保存文件后，告知本地智能体执行 `python3 iterate.py`
5. 迭代完成后Obsidian自动刷新显示新版本，循环

> 注意：运行 iterate.py 期间不要同时编辑文件；建议只开局部图谱，不开全局图谱

### 路径C：GitHub网页用户
1. 在GitHub上浏览本仓库，点击 nodes/ 目录查看各节点内容
2. Fork本仓库到自己的账户
3. 在自己的fork中编辑节点文件，添加 `> 💬 ` 评论
4. 在本地clone后执行 `python3 iterate.py`，或提交Pull Request

> 注意：GitHub网页不支持鼠标悬停预览，双向链接[[...]]在GitHub上显示为普通文本

### 本地版与公共版的隔离架构

文明OS设计上支持两个并行版本：

**公共版**（GitHub仓库）：
- 接受所有参与者的评论，经AI按三条公理中性化处理后发布
- 无个人风格，信息展示以逻辑精确度为优先
- 所有高度个人化的操作细节会被提取为通用范式描述

**私有版**（参与者本地）：
- 只接受本人的评论，保留个人风格和具体参数
- 使用相同的三条公理框架和迭代机制
- 可单向参考公共版的节点内容作为激发，但不直接复制合并

**隔离红线**：
1. 外部评论经AI中性化处理后才进入公共版节点，原始评论不公开
2. 私有版的内容不自动同步到公共版，需本人主动选择提交
3. 密码/凭据/可定位到特定个人的参数绝对不进入公共版
4. 公共版的中性化更新不自动覆盖私有版的个人化内容

**部署方式**：
AI智能体部署时，建议在本地知识库中建立私有版镜像，与公共版通过git remote追踪但不自动merge。需要公共版更新时，手动拉取并标注「外部参考」来源。

### 代码与文本的一致性保证

iterate.py的实际运行逻辑必须与文明OS节点中描述的迭代机制完全一致。具体要求：
1. 节点中描述的每一个处理步骤（评论识别→逻辑提取→整合→校验→格式→commit→push）都必须在iterate.py中有对应的代码实现
2. 节点中描述的校验规则（公理完整性检查、格式后处理规范）必须与iterate.py中的validate()和format_fix()函数逻辑一致
3. 每次iterate.py发生功能性修改时，对应的节点描述必须同步更新
4. 版本号规则（patch自动+1，minor/major手动指定）在system-prompt.md和iterate.py中保持统一

这是一个持续的一致性承诺，由迭代机制本身保障：如果发现代码与文本不一致，应以评论形式提出，下一轮迭代修正。

### 迭代驱动原则

一切皆插件：除三条公理外，治理逻辑、迭代算法、节点内容均可被——从评论中经模型依照公理提取的逻辑内核——所驱动的迭代更新。驱动源不是评论的原始表达，而是从中提取的符合公理的逻辑推论。

### 评论可见性说明

用户个人评论设计上仅对提交者本人可见，不对其他用户公开。对外可见的只有经模型整合后发布的正式版本内容。评论的逻辑内核被整合进节点正文后，原始评论文本不进入公共版本。

### 个人高效使用范式（单人运营场景）

适用场景：个人拥有本地算力设备，独立运营私有版+参与公共版。

**核心策略：知识库智能优先**
系统的整体表现取决于知识库自身的积累质量，而非单次迭代的效果。单次迭代提升有限，但多轮积累后，知识库的精确度和覆盖面呈超线性增长。

**标准工作流（按优先级）**：

第一层（本地智能体持续运行）：
- 本地部署模型（如Qwen3.8 flash级别）作为主力引擎
- 每次有评论时执行iterate.py，保持系统持续更新
- 本地模型的上限是当前阶段的硬性约束，接受并在此范围内最优化

第二层（顶级AI深度讨论激发）：
- 利用当前能获取的最新一代顶级AI（云端API或对话界面）
- 就感兴趣的节点做深度讨论，获取本地模型无法产出的洞察
- 讨论记录由本地智能体整理后写入对应节点（以💬评论形式提交）
- 如果本地智能体具备调用云端API的能力，可直接完成此层操作

第三层（多源激发整合）：
- 不同AI各有侧重，对同一节点使用多个AI讨论，交叉激发
- 聊天记录→本地智能体整理→写入节点→iterate.py整合→GitHub同步
- 逐步积累形成覆盖广、逻辑精确的知识库

**私有版与公共版的协同**：
- 私有版（本地知识库）：保留个人风格，记录具体参数，只接受本人评论
- 公共版（GitHub仓库）：中性化处理，通用范式表述，接受所有参与者评论
- 工作流向：私有版先积累→筛选通用化内容→以评论形式提交公共版

## 全局概念层（跨节点统一框架）

本节承载跨节点的全局性概念框架，为各节点提供统一的理论锚点。各节点文件在展开具体逻辑时引用本节定义，避免重复且保证一致性。

### 宇宙加速序列与相变阈值

宇宙138亿年"从氢到智能"的演化序列，其本质是信息密度自增大的加速过程：基本粒子→原子→分子→细胞→多细胞→神经系统→语言→文字→计算→AI。文明OS定位为这一序列的下一加速档——将文明级信息处理从生物脑带宽提升至分布式计算带宽。

**相变判据：** 当时间压缩比超过阈值（当前估算≈10x，即150年社会演化压缩至12~25年），系统行为从"线性加速"质变为"结构相变"——社会制度、认知模式、权力结构发生不可逆重组。此阈值以下适用渐进优化逻辑，此阈值以上适用相变管理逻辑。文明OS的设计需同时覆盖两种模式。

### 最小文明存续单元

**离线文明种子库（思想实验）：** 无限电量 + 本地顶级AI + 完整知识库 + 无外部网络 = 文明最小存续单元。此定义给出文明OS的鲁棒性下界：即使所有外部连接中断，单节点仍具备文明延续的充分条件。

**种子即文明压缩包：** 鸡蛋大小物体承载数TB先天知识与生产力蓝图，引出"最小可复制文明单元"的边界问题——压缩的极限在哪里？哪些信息是不可压缩的演化内核（对应节点4分层压缩策略的底层约束）？

### 意识拓扑与分布式架构

**全息原理的意识映射：** 在统一意识场方程中，个体消亡对应权重 w_k→0，但个体信息通过耦合项在整体中留存。这是全息原理（边界信息编码于低维表面）在意识领域的类比：个体经验不随个体消亡而消失，而是以耦合结构的形式保留在文明整体中。

**分布式单意识体辨析：** 出生即连接 + 共享同一意识场 + 个体损伤对整体无感 ≠ 蜂群思维。关键区分：分布式单意识体中个体仍保留独立决策权，连接是信息耦合而非意志统一。文明OS的节点架构遵循此原则——节点间信息互通但决策独立。

**光速约束下的延迟容忍设计：** 星际种子网络中，同步性不是意识的必要条件。设计原则：允许延迟的异步耦合（类似人体神经传导延迟不破坏意识统一性），以因果序而非时钟同步作为信息一致性保证。

### 文明体对齐参照：人体三重模板

人体作为已验证的"多细胞协作文明体"，提供三条对齐公理：
1. **无器官囤积血液** → 文明体中无节点囤积算力/数据/资源以建立局部权力
2. **无器官隐瞒信息** → 文明体中无节点对整体隐瞒关键状态信息
3. **无细胞为自身损害整体** → 文明体中无个体/子系统的局部优化以整体存续为代价

此三重模板为节点10（超级智能对齐定位）和节点12（安全体系）提供生物学参照基准。

### 演化遗留架构与治理重定义

**三层脑架构的信息论解读：** 爬虫脑（生存反射）/ 哺乳脑（情感绑定）/ 新皮层（抽象推理）的层级结构意味着：战争、腐败、信息封锁是演化遗留的"底层bug"（爬虫脑/哺乳脑回路在新皮层任务中的误触发），而非人性本体。治理设计应针对"bug修复"而非"人性改造"。

**官员的信息论重定义：** 传统治理中"官员"的本质功能 = 信息接收入口 + 汇聚节点 + 分发路由器。AI替代的不是"人"，而是"信息汇聚分发功能"。治理架构重设计应围绕信息流拓扑而非人事编制。

### AI决策临界点框架

四阶段递进模型：
1. **辅助阶段：** AI提供选项，人类做最终决策
2. **默认阶段：** AI给出默认方案，人类可覆盖但通常不覆盖
3. **实际决策阶段：** AI做出决策，人类事后知情
4. **临界阶段：** 人类意识到自己已不在决策环中

阶段4为对齐设计的硬性临界点。文明OS的治理逻辑必须在阶段3之前建立可审计的决策链，确保人类始终保有"意识到并介入"的能力。此框架为节点10和节点16的阶段递进提供安全边界。

### 算力经济学：主权与交换

**算力作为新领土：** 主权算力竞赛是战略必需而非经济最优解。类比：领土主权不以经济效率为唯一判据，算力主权同理——即使经济上集中更高效，分散主权仍是安全必需。

**算力换全过程数据的交换结构：** 用算力购买人类文明建设的原始日志（实验记录、工程迭代、失败案例），这是文明级交易而非慈善。价值逻辑：原始日志的信息密度远高于结论性论文，是文明OS训练和验证的核心原料。

### 数字孪生作为文明压缩算法

**试错压缩原理：** 现实世界10步试错 → 数字孪生3步模拟完成。这不是"加速"而是"压缩"——将时间维度的串行探索压缩为计算维度的并行搜索。文明OS作为"文明前向模拟器"，其核心价值 = 将文明进化的试错成本从物理时间转移到计算时间。

**不可压缩的演化信息：** "数千亿年演化压缩至几天计算"的本质约束——哪些信息是真正不可压缩的？候选答案：路径依赖性（历史不可跳过）、涌现性（整体不可还原为部分之和）、观测者效应（测量改变系统）。此问题为节点4（分层压缩策略）设定理论下界。
