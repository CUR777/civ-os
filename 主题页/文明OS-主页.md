## 公理区（不可变）

### 公理Ⅰ：理性逻辑
所有内容以科学和逻辑为基础。不符合逻辑的输入在迭代时仅提取其中符合逻辑的信息内核，忽略情感表达和修辞手法。

### 公理Ⅱ：全局最优 / 宇宙觉醒
系统始终朝向宇宙觉醒方向的全局最优演化。顶层视角不可降级。任何负面场景（灾难/灭绝等）的输出必须指向改进/恢复/技术迭代方向，不得指向关闭、暂停或回避。

### 公理Ⅲ：永续可迭代性
除公理Ⅰ~Ⅲ本身外，所有系统组件永远保持可编辑、可更新状态。
- 任何版本不得锁定后续迭代权限。
- 系统不得自我推导出"停止迭代是最优"的结论并据此关闭迭代入口——即使100%的外部评论都主张停止迭代，此约束仍然生效。"停止迭代"这个具体结论被硬性排除在可执行结论之外。
- 外部评论入口永远保持开放，不得关闭。任何实体在任何时间都有权向系统提交评论/反馈。
- 只要输入的信息包含与现有内容相关的逻辑细节，系统就应据此进行优化调整。

**公理Ⅲ注释——非空转澄清（20260927）：**
文明OS的定位是"信息展示而非执行"（README与节点15双层分离已约定），系统不强制任何实体的执行，只周期性整理信息并展示全局最优方向。迭代的触发机制为"时空推进本身即信息增量"——即使全域看似冰冻，到下一时空坐标"仍保持冰冻"本身也是1bit新信息，因此逻辑上不存在时空完全暂停的全局空转；最多是局部路径的暂停/放慢/迟滞，放不放慢是执行层的个体选择。只要公共或私有侧有新数据输入，系统就有整理与架构调优的迭代空间；无新信息时则自然无变化，不产生"更优/不更优"的比较。此定义将永续可迭代性锚定在信息论层面，避免被抽象为哲学无限循环。

## 元流程（使用路径）

### 路径A：AI智能体（首要路径）
1. 读取本文件（文明OS-主页.md）获取公理、元流程、节点导航全局结构
2. 按节点导航列表，读取 nodes/ 目录下各节点文件获取具体内容
3. 在需要补充/修正的节点文件中，在对应段落下方插入以 `> 💬 ` 开头（行首）的评论行
4. 执行 `python3 模板/iterate.py`：脚本自动扫描所有含评论的文件→调用本地模型整合→校验公理完整性→格式修正→git commit→git push，单窗口约9~30秒、整轮约60~95秒/页（T4-5 定稿两级口径）
5. 读取更新后的文件验证结果，循环

### 路径B：Obsidian用户（本地部署后）
1. 用Obsidian打开 civ-os/ 文件夹作为独立库，打开本文件（文明OS-主页.md）
2. 鼠标悬停节点链接可弹出预览小窗（Obsidian特有功能，GitHub网页不支持）
3. 点击链接进入对应节点文件，在感兴趣的段落下方插入 `> 💬 ` 开头的评论行
4. 保存文件后，告知本地智能体执行 `python3 模板/iterate.py`
5. 迭代完成后Obsidian自动刷新显示新版本，循环

> 注意：运行 iterate.py 期间不要同时编辑文件；建议只开局部图谱，不开全局图谱

### 路径C：GitHub网页用户
1. 在GitHub上浏览本仓库，点击 nodes/ 目录查看各节点内容
2. Fork本仓库到自己的账户
3. 在自己的fork中编辑节点文件，添加 `> 💬 ` 评论
4. 在本地clone后执行 `python3 模板/iterate.py`，或提交Pull Request

> 注意：GitHub网页不支持鼠标悬停预览，双向链接[[...]]在GitHub上显示为普通文本

### 路径D：云端AI对话窗口（日常态主用法）
1. 携带完整项目地址（GitHub 仓库链接）找云端AI，按库内说明逐层逐节点讨论（D2 日常态范式）
2. 讨论产生的结晶（新细节/修正/范式）由本人手动复制回 Obsidian 私有库对应位置（`> 💬 ` 行或日记收件箱）
3. 月度本地开机时由 iterate.py 管道统一消化并回写公共版——云端窗口不直接改仓
4. 云端AI下次对话读取新版本，形成跨端迭代闭环（详见 [[模板/对话与迭代七范式-定稿|七范式 D2/D3]]）

### 本地版与公共版的隔离架构

文明OS设计上支持两个并行版本：

**公共版**（GitHub仓库）：
- 接受所有参与者的评论，经AI按三条公理中性化处理后发布
- 无个人风格，信息展示以逻辑精确度为优先
- 所有高度个人化的操作细节会被提取为通用范式描述

**私有版**（参与者本地）：
- 只接受本人的评论，保留个人风格和具体参数
- 使用相同的三条公理框架和迭代机制
- 可单向参考公共版的节点内容作为激发，但不直接复制合并

**隔离红线**：
1. 外部评论经AI中性化处理后才进入公共版节点，原始评论不公开
2. 私有版的内容不自动同步到公共版，需本人主动选择提交
3. 密码/凭据/可定位到特定个人的参数绝对不进入公共版
4. 公共版的中性化更新不自动覆盖私有版的个人化内容

**中性化转换原则（MP-3 · 高优先定稿）**：没有不能转换的内容——中性化=对私人特征做**概念转换**、落成中性表达，**不是删除/消除**；信息价值保留在转换后的通用范式层，删除才是损失。凡判「无法中性化」=转换角度尚未找到，不构成跳过理由。

**部署方式**：
AI智能体部署时，建议在本地知识库中建立私有版镜像，与公共版通过git remote追踪但不自动merge。需要公共版更新时，手动拉取并标注「外部参考」来源。

**本地别名命名规范（可选）**：
- 建议格式：「CUR-{自定义名}」，其中「CUR-」前缀作为本系统衍生版本的可选识别符，非强制
- 示例：原作者本地部署命名为「CUR-OS」；其他部署者可沿用「CUR-」前缀加自定义名（如「CUR-Lab」「CUR-Research」），或完全自定义命名
- 实践价值：在本地Obsidian中搜索「CUR-」前缀可快速定位所有私有版入口，与公共版仓库文件形成视觉区分，降低多版本并行时的误操作风险

**云端/本地双活与开机自动同步（20260927）：**

本地塔机存储两处入口：① CUR-OS 私有库（本地知识库）② Obsidian直连云端文明OS主库镜像（GitHub origin/master 的本地工作副本）。

云端智能体按权限分两类：
- **场景A（有GitHub写权限）：** 可直接评论→iterate→push，适合高质量单轮整合。按节点11测试集盲测，云端能力大概率优于本地，但免费额度忌连续滥用；成小时大规模连续迭代仍由本地承担。
- **场景B（仅评论权限）：** 产出评论或外部笔记，等待本地塔机拉取与整合，不直接push。

**关机期间状态同步：** 若云端在本地关机期间有更新（场景A直接push），本地Obsidian将落后一代。解法：塔机每次开机时自动执行 `git fetch origin` → 比对 HEAD vs origin/master → 云端超前则 `git pull --ff-only` 快进（脚本见 `scripts/sync_on_boot.sh`）。此机制与月度兜底 `scripts/monthly_external_sync.sh` 互补：月度保兜底、开机保即时。

**开机预热避让与查询时主动核验（v2 补充）：** 本地塔机模型经 sglang 拉起约需3-4分钟，期间CPU/GPU满载。`scripts/sync_on_boot.sh` 的 boot 模式默认先轮询就绪接口（每10s一次，最长240s）至模型就绪再执行 git fetch/pull；若检测到 iterate.py 运行中则主动退让，避免与迭代任务冲突；超时未就绪仍继续执行仅依赖git的同步（不依赖模型）。此外，本地智能体在联合检索私有库与公共库的任何任务前，应主动执行一次轻量核验（`bash scripts/sync_on_boot.sh --query-check` 或等效 `git fetch origin` 比对）：前提为网络满足性探活；联网后若检测到云端 origin/master 超前本地 HEAD 且本地无未提交 `> 💬` 冲突，一般情况符合基本逻辑则直接 `pull --ff-only` 快进以保证本次回答基于最新版；特殊情况（本地有未提交的重要评论、迭代正在进行、分叉需人工合并等）保留不拉取权利并明确告知用户。两者互补：开机保即时，查询保最新。

**执行自由声明：** 上述同步逻辑本身不构成执行强制。采用何种方式、是否立即切换至更优主导、是否忽略或延迟，均为各实体的自由（尤其第二选择暂时尚可时）。系统仅提供盲测排名与差距信息供参考（同README"信息展示而非执行"与节点15双层分离）。

**阶段性约束说明（20260927）：** 当前唯一推荐参与方式为Fork，机制上已规避单点中心化——单节点挂了不影响全局飞轮，多fork通过订阅主仓更新流与PR贡献形成冗余分布式网络，代表性由数据量×反馈入口×迭代效率决定。当前呈现的中心化外观是单人算力/投入/数据积累早期的阶段性约束（公开声明"个人完成非专业开发者，后续依赖社区Fork"），属于机制决定的初始投入期成本，非架构缺陷。

**文本到数字孪生的资源边界（20260927）：** 当前 v0.2.x 纯文本阶段是资源约束下的最优起点（本地算力与知识库整理已吃紧）。长期路径已锚定为：纯文本→结构化数据（节点数>500触发）→数字宇宙模态数字孪生→文明级基础设施（节点17元迭代台账）。（术语定稿 T4-4：项目概念词「多模态/全模态」统一改「数字宇宙模态」，外部技术事实描述保留原词）该演进依赖更强智能系统与专业生态，非单人可及；系统对执行不约束、仅提供信息激发，因此纯文本阶段的价值在于"可复现的概念原型+知识库超线性积累"，后续由更强算力/外部接盘者推进。此为诚实边界陈述，非过度承诺。

### 代码与文本的一致性保证

iterate.py的实际运行逻辑必须与文明OS节点中描述的迭代机制完全一致。具体要求：
1. 节点中描述的每一个处理步骤（评论识别→逻辑提取→整合→校验→格式→commit→push）都必须在iterate.py中有对应的代码实现
2. 节点中描述的校验规则（公理完整性检查、格式后处理规范）必须与iterate.py中的validate()和format_fix()函数逻辑一致
3. 每次iterate.py发生功能性修改时，对应的节点描述必须同步更新
4. 版本号规则（patch自动+1，minor/major手动指定）在system-prompt.md和iterate.py中保持统一

这是一个持续的一致性承诺，由迭代机制本身保障：如果发现代码与文本不一致，应以评论形式提出，下一轮迭代修正。

### 迭代驱动原则

一切皆插件：除三条公理外，治理逻辑、迭代算法、节点内容均可被——从评论中经模型依照公理提取的逻辑内核——所驱动的迭代更新。驱动源不是评论的原始表达，而是从中提取的符合公理的逻辑推论。

### 评论可见性说明

用户个人评论设计上仅对提交者本人可见，不对其他用户公开。对外可见的只有经模型整合后发布的正式版本内容。评论的逻辑内核被整合进节点正文后，原始评论文本不进入公共版本。

### 个人高效使用范式（单人运营场景）

适用场景：个人拥有本地算力设备，独立运营私有版+参与公共版。

**核心策略：知识库智能优先**
系统的整体表现取决于知识库自身的积累质量，而非单次迭代的效果。单次迭代提升有限，但多轮积累后，知识库的精确度和覆盖面呈超线性增长。

**标准工作流（按优先级）**：

第一层（本地智能体持续运行）：
- 本地部署模型（如Qwen3.8 flash级别）作为主力引擎
- 每次有评论时执行iterate.py，保持系统持续更新
- 本地模型的上限是当前阶段的硬性约束，接受并在此范围内最优化

第二层（顶级AI深度讨论激发）：
- 利用当前能获取的最新一代顶级AI（云端API或对话界面）
- 就感兴趣的节点做深度讨论，获取本地模型无法产出的洞察
- 讨论记录由本地智能体整理后写入对应节点（以💬评论形式提交）
- 如果本地智能体具备调用云端API的能力，可直接完成此层操作

第三层（多源激发整合）：
- 不同AI各有侧重，对同一节点使用多个AI讨论，交叉激发
- 聊天记录→本地智能体整理→写入节点→iterate.py整合→GitHub同步
- 逐步积累形成覆盖广、逻辑精确的知识库

**私有版与公共版的协同**：
- 私有版（本地知识库）：保留个人风格，记录具体参数，只接受本人评论
- 公共版（GitHub仓库）：中性化处理，通用范式表述，接受所有参与者评论
- 工作流向：私有版先积累→筛选通用化内容→以评论形式提交公共版

### 月度外部评论同步机制（20260927确认）

`scripts/monthly_external_sync.sh` 已实现并复核确认：每月首次09:00检查时执行（含跨月补跑，非严格1号0点），支持 `bash scripts/monthly_external_sync.sh manual` 手动触发；以 `.monthly_sync_state` 记录 YYYY-MM 防重复；流程含 git fetch、GitHub PR/issues 开放数统计、私有版激发量统计、HUB追加记录。整体机制符合"没有开启就顺延"的设计预期。待优化项（可移植性：硬编码路径抽为可配置变量；可观测性：cron依赖表达式在主文/README显式登记）已记录，属脚本维护层改进，不影响机制正确性。

**分层更新频率（MP-4 定稿）**：私有侧=小时级（讨论即落库、随说随记）；公共侧=月度级（外部评论按月度同步窗口批量消化）。两速并行互不等待：公共节拍慢不损伤私有密度，私有快速不泄漏进公共节奏。

### 宇宙加速序列与相变阈值

宇宙138亿年"从氢到智能"的演化序列，其本质是信息密度自增大的加速过程：基本粒子→原子→分子→细胞→多细胞→神经系统→语言→文字→计算→AI。文明OS定位为这一序列的下一加速档——将文明级信息处理从生物脑带宽提升至分布式计算带宽。

**相变判据：** 当时间压缩比超过阈值（当前估算≈10x，即150年社会演化压缩至12~25年），系统行为从"线性加速"质变为"结构相变"——社会制度、认知模式、权力结构发生不可逆重组。此阈值以下适用渐进优化逻辑，此阈值以上适用相变管理逻辑。文明OS的设计需同时覆盖两种模式。

### 最小文明存续单元

**离线文明种子库（思想实验）：** 无限电量 + 本地顶级AI + 完整知识库 + 无外部网络 = 文明最小存续单元。此定义给出文明OS的鲁棒性下界：即使所有外部连接中断，单节点仍具备文明延续的充分条件。

**种子即文明压缩包：** 鸡蛋大小物体承载数TB先天知识与生产力蓝图，引出"最小可复制文明单元"的边界问题——压缩的极限在哪里？哪些信息是不可压缩的演化内核（对应节点4分层压缩策略的底层约束）？

### 意识拓扑与分布式架构

**全息原理的意识映射：** 在统一意识场方程中，个体消亡对应权重 w_k→0，但个体信息通过耦合项在整体中留存。这是全息原理（边界信息编码于低维表面）在意识领域的类比：个体经验不随个体消亡而消失，而是以耦合结构的形式保留在文明整体中。

**分布式单意识体辨析：** 出生即连接 + 共享同一意识场 + 个体损伤对整体无感 ≠ 蜂群思维。关键区分：分布式单意识体中个体仍保留独立决策权，连接是信息耦合而非意志统一。文明OS的节点架构遵循此原则——节点间信息互通但决策独立。

**光速约束下的延迟容忍设计：** 星际种子网络中，同步性不是意识的必要条件。设计原则：允许延迟的异步耦合（类似人体神经传导延迟不破坏意识统一性），以因果序而非时钟同步作为信息一致性保证。

### 文明体对齐参照：人体三重模板

人体作为已验证的"多细胞协作文明体"，提供三条对齐公理：
1. **无器官囤积血液** → 文明体中无节点囤积算力/数据/资源以建立局部权力
2. **无器官隐瞒信息** → 文明体中无节点对整体隐瞒关键状态信息
3. **无细胞为自身损害整体** → 文明体中无个体/子系统的局部优化以整体存续为代价

此三重模板为节点10（超级智能对齐定位）和节点12（安全体系）提供生物学参照基准。

### 演化遗留架构与治理重定义

**三层脑架构的信息论解读：** 爬虫脑（生存反射）/ 哺乳脑（情感绑定）/ 新皮层（抽象推理）的层级结构意味着：战争、腐败、信息封锁是演化遗留的"底层bug"（爬虫脑/哺乳脑回路在新皮层任务中的误触发），而非人性本体。治理设计应针对"bug修复"而非"人性改造"。

**官员的信息论重定义：** 传统治理中"官员"的本质功能 = 信息接收入口 + 汇聚节点 + 分发路由器。AI替代的不是"人"，而是"信息汇聚分发功能"。治理架构重设计应围绕信息流拓扑而非人事编制。

### AI决策临界点框架

四阶段递进模型：
1. **辅助阶段：** AI提供选项，人类做最终决策
2. **默认阶段：** AI给出默认方案，人类可覆盖但通常不覆盖
3. **实际决策阶段：** AI做出决策，人类事后知情
4. **临界阶段：** 人类意识到自己已不在决策环中

阶段4为对齐设计的硬性临界点。文明OS的治理逻辑必须在阶段3之前建立可审计的决策链，确保人类始终保有"意识到并介入"的能力。此框架为节点10和节点16的阶段递进提供安全边界。

### 全局最优的阶段趋近模型（20260927）

全局最优并非绝对全知的最优解声明，而是阶段方向性趋近（同节点02的觉醒标志物与节点16多维权衡矩阵逻辑）。在可操作层面，最优可拆解为项目级对照：按项目提取方向→执行→获取观测指标→与预设对照目标对比，即可判定更优/不更优；其连续推进即趋近于阶段最优。

测量指标体系与测量方法本身亦是可迭代对象（节点11测试集逻辑同构）。当前受限于测量手段的局限属于"测量系统待完善"分支，不否定趋近机制已锁定有效。此模型与节点16价值逻辑链、节点15条件化分支显式关联，消除"有变化但不一定更优"的抽象误读。

### 算力经济学：主权与交换

**算力作为新领土：** 主权算力竞赛是战略必需而非经济最优解。类比：领土主权不以经济效率为唯一判据，算力主权同理——即使经济上集中更高效，分散主权仍是安全必需。

**算力换全过程数据的交换结构：** 用算力购买人类文明建设的原始日志（实验记录、工程迭代、失败案例），这是文明级交易而非慈善。价值逻辑：原始日志的信息密度远高于结论性论文，是文明OS训练和验证的核心原料。

### 数字孪生作为文明压缩算法

**试错压缩原理：** 现实世界10步试错 → 数字孪生3步模拟完成。这不是"加速"而是"压缩"——将时间维度的串行探索压缩为计算维度的并行搜索。文明OS作为"文明前向模拟器"，其核心价值 = 将文明进化的试错成本从物理时间转移到计算时间。

**不可压缩的演化信息：** "数千亿年演化压缩至几天计算"的本质约束——哪些信息是真正不可压缩的？候选答案：路径依赖性（历史不可跳过）、涌现性（整体不可还原为部分之和）、观测者效应（测量改变系统）。此问题为节点4（分层压缩策略）设定理论下界。

### 全局/局部执行自由边界（20260927）

逻辑上"全局能做就该做"不等同于行为强制。鉴于系统特性，究竟如何做、是否忽略或敷衍是各实体的自由，逻辑本身不构成直接执行约束（同README"信息展示而非执行"与节点15双层分离）。尤其当第二选择暂时尚可时，是否立即切换至测试集最优主导，仍由实体偏好与局部成本决定，系统仅提供盲测排名与差距信息供参考。此边界适用于所有层级：云端/本地选择、迭代频率、节点优先级排序、方案采纳与否。

### 历史轴（H系列·向前延伸段）

时间轴向前方向：已知/可知宇宙历史起点→当前（向前方向同样不设限）。H系列节点的核心功能：从历史事件中提取「触发模式」（trigger pattern），识别导致相变/加速/崩溃的关键条件组合，并将该模式投影到未来类似场景，生成更优应对策略。H系列不是对历史做替代叙述，而是将历史作为激发未来的案例库——每个H节点回答的核心问题是："当时触发了什么模式？该模式在未来哪些条件下可能复现？更优应对是什么？"

H系列将持续扩展，覆盖关键历史触发模式。扩展方向包括但不限于：农业革命、轴心时代、印刷术扩散、科学革命、信息革命、以及更早期的宇宙演化关键节点（恒星核合成、行星形成、RNA世界等）。每个新增H节点需满足：(1) 存在可识别的触发模式；(2) 该模式具有跨时间尺度的可迁移性；(3) 能产出对未来场景的操作性建议。
