# OpenClaw 记忆架构笔记（精确版）

> 来源=本机 2026.9.1 自带文档 `concepts/memory-architecture.md` + `concepts/active-memory.md`，10-09 实读提取。版本演进以官方仓为准。

## 总览
记忆 = 代理工作区内一组**纯文本文件 + 一个 SQLite 索引**，按层级（tiers）组织；每层在信任级别、写入规则、注入行为三个维度上各不相同。

## 五条设计原则
1. **无隐藏状态**：模型只记得写进工作区文件的内容；任何记忆面都是文本编辑器可查可改的。
2. **写入是难的那一半**：对笔记文件的检索效果与更重的设计相当，真正拖垮记忆系统的是写入时的策展不可靠。长程评测（LongMemEval, arXiv:2410.10813）一致显示「写了什么」比「怎么索引」更重要→策展被移出繁忙回复路径，交给专门的后台工序完成。
3. **写路径=安全边界**：内容级扫描无法可靠捕获被投毒的记忆，所以在写入时强制来源溯源（provenance）+晋升时设结构性闸门，而非事后检测坏记忆。
4. **确定性闸门，模型判断在闸门内**：打分、阈值、资格、匹配、生命周期全是确定性代码；语言模型只在确实需要语言判断处使用，且始终处于确定性代码约束的边界内。
5. **失败永不阻塞回复**：回复路径上的每一步记忆操作都有超时和/或回退；记忆子系统宕机=降级不瘫痪。

## 召回双腿
- **确定性记忆腿（平铺检索）**：对直接事实匹配最强，对时间性/跨会话问题较弱。
- **Active Memory 深召回腿**：默认 `mode=escalate`——仅当消息问及过去、且确定性腿没找到强可信触发匹配时，才启动阻塞式子代理召回；普通回复保持快，同时为既往决策/时间性/多跳问题保留深搜路径。不可搜时插入隐藏的结局标注而非泄露供应商错误。跨会话有界召回由 per-agent 设置 `rememberAcrossConversations` 控制（个人安装默认开，配合受保护转录召回路径与 `memory_search` 工具）。
