# 定时任务退休先全量归档后删除

触发线索：含「删除/移除/永久删」且对象是定时任务，或退役版本的集中清面。「彻底停」类歧义措辞未明说删除时，默认用禁用（可逆）形态并声明理解。停用与删除是两道工序，本件只管删除。

## ① 有序工序（顺序刚性）
1. 双源清点：先导出启用面，再导出含禁用的全量。默认列表会隐藏禁用残影，只查默认必漏。
2. 圈定对象并过滤保护：按名称匹配退役世代；名字里带「承袭/引用」字样的现役件不得入删除集；逐枚 grep 提示词，凡硬编码引用目标 id 的任务列入同批处理，删后不留悬空引用。
3. 逐枚全量导出（删除前一刻的活值）：完整 job 的 JSON、提示词全文单文件、汇总表（id、名称、排程、长度、校验和），落带时间戳的备份目录。
4. 备份自检：文件非空、JSON 可解析、长度与活值一致，三绿才准动刀。
5. 删除：前五步全绿后执行。
6. 当拍回写：归档件、排程应然表注记、相关台账追记、持久记忆时间戳行。

## ② 验收闸
删后全量复测：目标 id 逐枚缺席；枚数差=删除数；现役件逐枚在位；目标名义残留（排除保护字样后）为零。

## ③ 回滚与案型摘要
回滚=按完整 JSON 原字段重建；含引用件先修其提示词内的 id 指向再重建。归档件必含对象表、备份路径、恢复姿势、执行账。案型：「已废止」口令不等于「已删除」，授权废止后本体可能仍在盘上，账面写「不在册」之前必须用含禁用的全量列表实测一次。
