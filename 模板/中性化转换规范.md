# 中性化转换规范（T5-5 范式定稿操作化 · 10-10 入库 P2-47）

> 定稿原文（环5 T5-5 确认，宿主评价「非常好，非常精确，清晰度非常高」）：**公共↔私有转化质量保障 = 1对1 逐句中性化，逐最小语义单元转化，不丢细节。**
> A62-1 修正：公共版转化**不能压缩**——安全性论证类内容逐句对应，论点链条每一环都必须在公共版有对应句；概括合并=违规。

## 操作定义
1. **最小语义单元** = 一句承载一个完整判断/事实/约束的表述（含数据+条件、机制+对象、动作+边界）。拆分以「去掉任何一半都损失一个独立信息」为准。
2. **1对1 对应**：私有版 N 个语义单元 → 公共版 N 个中性化单元；单元数差 = 丢细节量，必须归零。
3. **转换而非删除**（MP-3 同源）：私人特征（人名/地点/金额个人账/设备序列/个人状态）→ 抽象为角色位/量级/条件式；信息骨架与逻辑链一律保留。
4. **唯一豁免类**：密码/凭据/可定位到特定个人的参数（隔离红线③）= 不转换直接隔离，其余无「无法中性化」。

## 自检工序（每次私有→公共回写必跑）
① 私有段逐句编号 U1..Un → ② 公共段逐句编号 P1..Pm 并标注各 Pi←Ui 映射 → ③ n−m>0 即丢细节，回补至 0 → ④ 反向查：公共段无映射句=夹带私人特征，回炉 → ⑤ 敏感词复扫（红线③清单）零命中才准 commit。

## 反向（公共→私有）同步
公共版新段落默认整段镜像回私有版（append-only，不覆盖私有注记）；私有注记行以 `（私有注记）` 前缀标记，永不进公共。

## 单条转化五步流程（条228〔B1〕定稿 · 1011 R5缺口补落）

核心原则：**保证质量优先于保证速度。**

1. 拿到要转化的条目；
2. 搜索目标库（公共→私有：搜私有全库所有相关细节；私有→公共：搜公共全库所有相关细节）；
3. 所有相关信息汇总后，做精细整合；
4. 该放模板的抽象成模板，该特化的做特化解释；
5. 单条可能很重（全库搜索+整合），但保证质量。

配套进度管理（分段循环制）与质量-速度飞轮条款见同目录 `README.md` 「转化进度管理（分段循环制 · 1011 补落）」段；三条同源=R5-B 段〔条228/230/231〕。
