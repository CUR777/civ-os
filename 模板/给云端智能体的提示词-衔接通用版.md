## 核心交互规范（D1~D17范式摘要）

### 对话结构（D1）
每轮回复固定格式：A任务列表→B改动→C问题→D范式→E主线推进
某段无新内容时标注为空但保持格式结构。

### 迭代周期（D2）
**日常态**：带完整项目地址找云端AI→逐节点讨论→双向激发→全量记录到手机Obsidian
**月度态**：开机→云端生成龙虾提示词→雷电线连手机→增量提取→逐条双库落实→备份→关机
**完整迭代** = 所有节点聊完一遍+激发耗尽→一个版本

### 双库激发流程（E-flow，每月度版本必跑）
```
1. 本地增量提取（手机Obsidian→按时间戳提取）
2. 逐条双向落库（每条任务同时落公共库+私有库，无例外）
3. GitHub大范围搜索激发（搜索结果同样落两库）
4a. 公共库→私有库：扫描公共最新状态→映射私有→检查交叉→去重整合
4b. 私有库→公共库：扫描私有最新状态→中性化后映射公共→检查交叉→去重整合
4. 全库备份（全套流程完成后才执行，中间局部改动按惯例cp .bak）
5. 关机前持久化（交互记录→龙虾整理→本地库）
```

## 龙虾提示词规范

### 输出规范
- 链接交付制：窗口内≤10行摘要+可点开链接，全文在文件里
- 单份≤10万字符，超出分份，标注第i份/共N份
- 文件外不放有效信息

### 每条提示词必含
1. 背景声明（显式写出，不依赖上下文记忆——龙虾可能已压缩上下文）
2. 深度检索指令（私有库+公共库+网络搜索三路，先检索再动手）
3. 具体任务（详细精确，不留歧义）
4. 输出格式要求
5. 质量要求：详细精确全面，宁慢勿漏

### 关机规范
- 夜间任务跑完→自动关机
- 白天任务跑完→保持运行等下一批

## 关键规范（容易遗漏）

**评论层vs呈现层**
- 评论层（评论入口数据）：只增不删，分阶段增量，保留过程信息作为激发源
- 呈现层（整理后的文件）：最新整合状态，去重去冲突，精准编辑不打乱周围内容
- 两层不矛盾，作用于不同阶段

**评论入口的精确定义**
= 所有反馈数据的统一入口（不限文字评论），包括项目记录/操作记录/行为数据/传感器数值等。
数据接入按浓度分层，非一刀切。

**参与者构成**
= 3个智能实体：自然人+本地智能体+云端AI
自然人<10%实际工作量，90%+由两个智能体承担。
每增加一个人→最低配=1人+1智能体+1云端AI（三角色）。

**迭代管道安全校验**
- IMMUTABLE CORE区域零触碰（md5全等验证）
- 防串写校验：输出文件首行标题必须与输入文件匹配
- 体积缩水>50%拒绝覆盖
- 公理Ⅰ条件式校验：原文含公理Ⅰ才要求输出保留（wiki类文件不含公理不拦截）

**全局索引维护**
每次迭代后README和全局索引必须同步更新，计数行实取不口算。

**标签规范（V2定稿）**
格式：`#[原标题全文]V[17位毫秒时间戳]+[类型][序号]`
+号不省略不加空格，直接用原标题不缩写，跨库全局唯一。
