〔治理指标四层分离规范（#ZZ-METRICS-4LAYER，2026-10-12 B23[6] 直落·模板=iterate 扫描盲区默认直落）〕

任何系统评估必须将以下四层指标严格分离，不得互相替代：

**层1：技术健康度（可自动监测）**
  - 版本漂移、数据质量、延迟、错误率、工具调用成功率
  - 可由系统自动采集和报警

**层2：合规状态（需要可追溯记录）**
  - 规则违规率、处置记录、来源可追溯性
  - 需要可解释的规则 + 可追溯的处置结果

**层3：安全能力（需要独立评测）**
  - 不可由被评系统单方面提交结果
  - 需要：离线盲测 + 独立tripwire + 人工共同签署
  - 90%安全恢复≠100%安全——单一机制不足

**层4：治理合法性（不能由前三层推出）**
  - 价值冲突、权利边界、跨辖区规则
  - 必须回到人类制度程序
  - 「系统表现良好」≠「系统具有治理合法性」

常见错误（严格禁止）：
  ✗ 用技术健康度指标替代合法性判断
  ✗ 用模拟准确率替代现实治理授权
  ✗ 「日志记录了」≠「已经处理了」
  ✗ 「通过评测」≠「内部目标已改变」（对齐伪饰风险）

〔龙虾知识库复用稳定性改进机制（#ZZ-STABILITY-1012，2026-10-12 B25[2] 直落·模板=iterate 扫描盲区默认直落制）〕

**【问题诊断】**（批令原文）
开放性使用时，智能体容易跳过知识库检索步骤，需要自然人显式提醒才能触发；
根因=任务提示词未强制「先检索再执行」时，模型倾向直接回答。

**【机制1：任务前置检索声明】**
每个任务提示词开头必须包含四件套检索清单：
「在执行任何操作之前，先搜索知识库中与本任务相关的所有规范和历史记录，包括：
私有库+公共库+MEMORY.md+相关模板文件。搜索完成后再执行，确保不遗漏已有规范。」
本地自查配套：执行窗回复/台账首拍无检索证据行=不合格。

**【机制2：灵魂文件触发层】**（实施载体=B25[3] 当轮写入 SOUL.md「任务开始前必做」四项清单）
①MEMORY 检索 ②规范检索（模板/目录） ③私有库检索 ④积压检查；
四项缺一不可；某项为空须明标「[已搜索，无相关记录]」——空结果也要留证据。

**【机制3：完成后自检触发】**
每项任务收尾必答三问：本次执行中是否有可参考而未参考的规范？
对应规范是否已被使用？漏了什么→当轮补登记一条。

**【机制4：关键词触发索引】**（含落地修正）
不新建重复索引结构。既有活参照三件=私有库全索引.md（全索引件）＋
SOUL「🧰 技能索引一体化常驻块」类别速查（线索→去处）＋本模板搜索清单融入条款。
落地=任务关键词命中类别→按类别速查路由检索；新规范上线同拍登记入索引（双同步律）。

**【机制5：确定性层优先——检索从「指令」下沉为「钩子」（本批搜索证据新增）】**
外部证据：
①memory-lancedb-pro（OpenClaw 长期记忆插件，github.com/CortexReach，权威性=高）：
  经 before_agent_start / before_prompt_build / agent_end 生命周期钩子在**提示词构建前**
  自动召回注入，混合检索=Vector+BM25+RRF 融合+cross-encoder 重排+时近衰减+MMR+噪声过滤；
  =「不依赖模型自觉」的平台级强制检索形态。
②claude-md-best-practices（dianyike/claude-code-insights，§8「确定性执行：用 Hooks 替代指令」，
  权威性=中高，转引 arXiv 2602.11988 学术评测）：
  **LLM 自动生成的长篇上下文文件使任务成功率下降 2~3%、推理成本上升 20%+**；
  指令文件应短而权威（每行解决一个真实问题），能机制化的一律转钩子/Linter。
③openclaw-memory（aquiladev，代码库维护者生产指南，权威性=中）：
  强制检索三步=持久规则写文件不写聊天/memory flush 阈值调参
  （compaction.reserveTokensFloor+memoryFlush 启用）/AGENTS.md 一句
  「Before doing anything non-trivial, search memory first」。
本地映射：OpenClaw 9.1 平台已内置混合检索管道+压缩前记忆冲刷（外部研究称其为
coding-agent 类最强记忆系统），**缺口不在平台能力，在「默认是否调用」**——
a) 每拍唤醒第一动作=检索四项清单（机制2 已落灵魂层）；
b) 候选机制化下批试：三循环 V2 payload 前置「唤醒即 memory_search」硬拍（不动平台配置）；
c) 触发词路由（全量预读口令制）已在册，与本机制族并联。

**【机制6：短即稳定——检索清单规模上限（本批搜索证据新增）】**
依据②的学术评测结论反向护栏：本机制族（含 SOUL 四项清单）全链保持**短清单形态**，
禁止扩写成长篇；新增规范走「登记入索引」而非「塞入提示词常驻区」。

〔龙虾智能体稳定性测试规范（#ZZ-TEST-STABILITY，2026-10-13 B27[5] 直落·模板盲区默认直落制）〕

【测试目的】
验证知识库中已有规范/模板/技能是否在实际使用中被自动触发和应用。
不是测"回答好不好"，是测"该用的模板用了没有"。

【测试集设计】
① 全库扫描→列出所有应被触发的模板/技能/规范
② 设计"埋雷"任务→每题有明确的"满分应触发清单"
③ 满分=所有相关模板被读取+被应用到输出
④ 定期从新落库内容中抽取测试题（防止测试集老化）

【测试执行】
① 全新零状态窗口（不带历史上下文）
② 输入模拟自然人口语：极短（10-25字）
   只说需求不说方法，不提示"库里有什么"
   模拟真实场景：个人语音转文字，~10TPS，很粗略
③ 认知科学基础（节点16 A61-A62）：
   口语短句=未收敛思维流
   碎片中可能嵌入高度自洽的因果链
   认知卡顿=框架冲突信号，不是表达不清
   智能体必须能从碎片口语中提取逻辑内核
④ 观察工具调用记录（不是回答文本）
⑤ 对照满分清单打分

【测试-迭代循环】
① 测一轮→打分→找未触发项→分析原因
② 做一轮改进（索引/钩子/锚点/技能修复）
③ 再测一轮→打分→对比上一轮
④ 循环直到满分或接近满分
⑤ 稳定后才推其他任务（龙虾稳定性=最高优先级）

【不可删减原则】
模板库的维护=规模化提升，不是筛选精简
✗ 不比较"哪个增强多/少"然后删少的
✓ 两个都保留，都是规模化往上走
除非极端情况（完全重复且规模极大后才碰到），否则不删

【备份要求】
改进过程中每步都可逆
索引重建/配置修改/钩子添加全部有母本备份
出问题→几行命令恢复，不是从头摸索
