# 置信度聚合器（Confidence Aggregator）

核心命题：任何关键状态判断都至少需要两个独立证据链交叉确认。

## 抽象结构
```
置信度聚合器(判断对象, 证据源集合E={e₁,e₂,...,eₙ}, n≥2)
  → 各证据源独立产出判定dᵢ
  → 聚合函数f(d₁,d₂,...,dₙ) → 最终置信度C∈[0,1]
  → 若C < 阈值 → 触发升级（引入更多/更高档位证据源）
```

## 独立性要求
证据源之间必须满足独立性假设（不同模型/不同工具/不同时间点），
否则聚合退化为单源重复确认，无法捕获系统性偏差。

## 实例映射
| 领域 | 证据源1 | 证据源2 | 聚合方式 |
|------|---------|---------|----------|
| 模型输出核验 | Model_A推理结果 | Model_B推理结果 | divergence Score + 双阈值 |
| 硬件状态检测 | npu-smi info | 实际推理测试 | 二者一致→确认；矛盾→升级 |
| 安全状态确认 | CVE版本对照 | 实际运行行为 | 矛盾即触发升级人工 |
| 迭代质量确认 | 本轮输出 | 历史基线比对 | 逻辑骨架比对 |

## 矛盾同真即信号
同一判断对象在不同时间/不同证据源出现矛盾→
不是选其一→而是标记"信息不足，需引入更多证据源"。
矛盾本身即为信号，提示当前信息不足以唯一确定答案。

## 降级情形
当前单模型环境下，近似替代方案：
- Temperature变化对比（0.1 vs 0.6）
- 系统提示词变体对比
- 分段内部一致性检测
- 时间维度一致性审计（相隔一周各跑一次）
