# 主题页信息源清单规范（B36 建 · #ZZ-BATCH36-1014-CE · 2026-10-15）

> 目的：任何主题推进/信息收集任务（日常推进/研究报告/定时搜索）开工前，该主题的 top 高质量来源不能漏。
> 通用必查源 + 本主题专属源 = 该主题的最小搜索面；只查通用源就收工 = 收工不合格。

## a. 通用必查源（所有主题必须覆盖，不可遗漏）
| 来源 | URL/API | 适用 |
|---|---|---|
| GitHub | github.com + api.github.com（仓库/代码/议题搜索） | 开源实现/工程细节 |
| Hugging Face | huggingface.co（模型/数据集/论文页） | 模型与权重生态 |
| arXiv | export.arxiv.org/api/query（含中文关键词交叉验证） | 前沿论文 |
| 魔搭 ModelScope | modelscope.cn | 境内在架/镜像下载 |
| AIhot | 已接入（见 AIhot 接入件） | 中文 AI 资讯精选 |
| 境内搜索 | search-cn.py（sogou 引擎链） | 中文语境/政策/社区 |
| 境外搜索 | VPN 腿（按配额：日预算沿册） | 英文一手来源 |

## b. 主题专属源（每个主题页末尾「## 信息源清单」段自行维护）
格式固定：`| 来源 | URL/API | 适用场景 | 权威度 | 最后验证 |`
- 专属源=该主题「特别突出」的来源（硬件→厂商文档+论坛；模型→HF/ModelScope/官方blog；安全→CVE/公告/NIST；方法论→arXiv/经典书目）。
- 不同主题不同答案；每页 2~5 条，宁缺毋滥，禁臆造小众站。

## c. 信息收集工序（嵌入既有搜索规范）
1. 开工前=先读该主题页「信息源清单」段（专属源+通用源=最小搜索面）。
2. 搜索完成后=对实际用到且命中有效的专属源，更新「最后验证」列（YYYY-MM-DD）。
3. 与龙虾搜索规范叠加生效互不覆盖；专属源只加不减通用面。

## d. 新源发现与退役规则
- 发现新高质量源：追加行 + 尾注来源批次（`+批次号`）。
- 连续 3 次按该源检索无有效结果：该行标注「降级观察」。
- 站点不可达：「最后验证」不更新 + 行尾标注 `(不可达 YYYY-MM-DD)`，URL 保留（可能临时故障）。
- 退役：降级观察再连续 3 批零命中 → 移入本段末尾「退役候补」折叠行，不直接删。
