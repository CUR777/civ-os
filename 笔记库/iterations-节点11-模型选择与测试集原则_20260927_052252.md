## 节点11：模型选择与测试集原则


【当前阶段·已实现】

### 当前部署实况

| 参数 | 值 |
|------|----|
| 模型 | Qwen 3.8 flash（125B主模型 + 51B N-gram嵌入，单token激活6B参数，FP4量化） |
| 推理引擎 | sglang |
| API端点 | `127.0.0.1:8001` |
| 单线程吞吐 | ~150 TPS |
| 4并行吞吐 | ~300+ TPS |
| 单窗口上下文上限 | ~52万 token |
| 总上下文容量 | ~80万 token |

当前为唯一可用模型，所有迭代均由此模型完成。

### 通用测试集原则（不限于特定模型）

1. **职位要求制：** 每个节点位置有对应的"职位要求"（所需算力、逻辑水平、领域知识），模型选择以匹配职位要求为准，而非盲目追求最大参数。
2. **最优连续运行：** 在手头能用的配置中，选最好的那个连续运行，避免频繁切换带来的上下文断裂。
3. **同档对比测试：** 如果有多个能力相近且无明显代差的候选模型，跑一轮标准测试集比较，以实测数据而非参数规格做决策。
4. **测试集可迭代：** 测试集本身也是可迭代插件——随新数据、新任务类型进入而更新，不固化为静态基准。
5. **硬件层级匹配：** 不同硬件层级对应推荐模型规模（见下表），确保每个节点在可用算力下获得最优推理质量。
6. **Optimizer Agent（后期）：** 自动检测硬件 → 匹配最优模型 → 部署 → 基准测试 → 分配任务，实现模型选择的去人工化。

### 硬件层级与模型匹配参考

| 硬件层级 | 推荐模型规模 | 适用场景 |
|----------|-------------|----------|
| 旧手机 | 1B Q4 | 极端边缘，最底层简单任务（单切片摘要、格式校验） |
| 新手机 | 3~4B Q4 | 轻量底层节点（短文本生成、简单分类） |
| 消费级PC无GPU | 7~8B Q4 | 中层辅助任务（摘要、翻译、结构化提取） |
| 消费级PC中端GPU | 14~32B Q4 | 中层主任务（逻辑推理、多步分析） |
| 专业级（96GB VRAM级别） | 125B+ FP4 | 顶层裁决、复杂交叉核验、长上下文整合 |
| 集群 | 满参数顶级模型 | 全量文明OS生成、超级智能对齐研究 |

设计约束：此表为当前技术条件下的参考映射，随硬件与模型演进按分层更新频率（底层高频）持续调整。

> ### 子节点11-01：测试集设计规范
> 测试集的插件属性：测试集本身是可迭代插件，随新实测数据进入而更新（公理Ⅲ保障）
> 职位要求定义：每个节点位置的position.json，包含所需算力/逻辑水平/领域知识/准确率下限
> 候选模型评分机制：通过率（pass rate）×准确率（accuracy）×速度（TPS）综合评分
> 标定方法：用已知正确答案的测试集确定各模型的能力边界，不使用自我评分
> 测试集更新触发：新模型发布/新实测数据进入/现有模型性能下滑超过阈值
>
> ### 子节点11-02：Optimizer Agent 6步工作流详细设计
> 步骤1：检测硬件配置（GPU型号/VRAM/带宽/存储/CPU型号/RAM）
> 步骤2：从文明OS测试集中匹配最适合该硬件的模型（按评分排序）
> 步骤3：自动下载并部署模型（量化级别按VRAM自动选择：Q4_K_M/Q5_K_M/FP4等）
> 步骤4：运行基准测试（TPS测定+准确率抽查+格式合规率）
> 步骤5：根据性能测试结果分配该节点的时空切片（越强的硬件负责越复杂的节点）
> 步骤6：定期重评估（触发条件：新模型发布/硬件配置变更/性能下滑检测）
> 类比：Kubernetes scheduler的设计思路，但面向AI推理节点而非通用计算
>
> ### 子节点11-03：当前单模型环境的质量保证方案
> 现状：只有一个可用模型（Qwen3.8 flash 125B，sglang@8001）【当前阶段·已实现】
> 替代方案1：temperature变化（0.1低温稳定版+0.6高温探索版，比较结果）
> 替代方案2：系统提示词变体（简版和详版各跑一次，检查逻辑一致性）
> 替代方案3：分段后检查跨段落的内部一致性（引用是否匹配，逻辑链是否断裂）
> 人工抽检的触发条件：校验失败/输出体积异常/首次分段迭代/重大结构改变
