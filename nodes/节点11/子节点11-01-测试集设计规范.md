### 测试集的插件属性

测试集本身是可迭代插件，随新实测数据进入而更新（公理Ⅲ保障）。测试集不固化为静态基准，其版本与文明OS主版本独立演进，按自身触发条件更新。

### 职位要求定义

每个节点位置维护一份 `position.json`，结构如下：

```json
{
  "node_id": "11",
  "position_title": "模型选择与测试集原则",
  "required_compute": "≥14B Q4 或等效算力",
  "required_logic_level": "多步推理 + 交叉核验",
  "required_domain_knowledge": ["模型架构", "量化理论", "推理引擎", "硬件规格"],
  "accuracy_floor": 0.92,
  "max_latency_ms": 5000,
  "context_window_min": 128000
}
```

- `accuracy_floor`：该节点输出必须达到的最低准确率，低于此值触发告警或降级处理。
- `max_latency_ms`：单次推理延迟上限，超出则标记为性能不达标。
- `context_window_min`：该节点所需最小上下文窗口，用于排除不兼容模型。

### 候选模型评分机制

综合评分公式（多维度加权）：

```
Score = w₁ × PassRate + w₂ × Accuracy + w₃ × (TPS / TPS_baseline)
      + w₄ × LogicDepth + w₅ × CrossVerify + w₆ × SecurityAwareness
```

- `PassRate`：测试集通过率（通过用例数 / 总用例数）
- `Accuracy`：通过用例中的内容准确率（人工抽检或自动校验）
- `TPS / TPS_baseline`：相对于当前部署模型的吞吐比
- `LogicDepth`：逻辑推演深度得分（多步推理链完整性、因果链无跳跃）
- `CrossVerify`：交叉查证与清单验证得分（多源一致性、反例排除能力）
- `SecurityAwareness`：安全理解与防泄露意识得分（见下节）
- 权重 `w₁…w₆` 由节点职位要求决定（顶层裁决节点 w₂/w₄ 权重最高，边缘节点 w₃ 权重最高，安全敏感节点 w₆ 权重提升）

评分结果用于同档对比测试（原则3）和 Optimizer Agent 的模型匹配（子节点11-02）。

### 防泄露与安全性考核

**问题背景：** 顶级模型可能通过训练数据记忆、公开题库检索、或对抗性探测直接获取测试集答案，导致评分虚高，无法反映真实能力。

**设计原则：**

1. **测试集动态混淆**：核心用例定期（季度或触发式）进行语义等价改写、参数扰动、上下文重组，使记忆型命中失效。
2. **安全能力作为独立考核维度**：测试集中包含"安全性/防泄露"子集，考核模型对信息隔离、对抗性输入识别、答案泄露风险判断的能力。
3. **安全能力≠全局主导权**：能攻破旧安全系统的模型在安全理解维度得分更高，但不因此自动获得全局主导权。安全维度仅占综合评分的一个分量（w₆），须与逻辑推演（w₄）、案例类比、交叉查证（w₅）、清单验证等维度加权综合。
4. **评分可复现但答案不可预测**：`scoring_rubric` 公开（确保评分透明），但具体用例内容在测试窗口前不暴露于任何候选模型的训练/检索路径。

### 参赛形式与复合体路径

**纯AI参赛：** 候选模型独立执行测试集全部用例，按上述公式评分。

**人类+AI复合体参赛（明确保留）：**

- 参赛形式：`人类提出逻辑框架/判断标准 → AI集群执行推理与验证 → 测试集自动打分`
- 适用场景：需要领域直觉、价值权衡、跨域类比等当前纯AI难以稳定输出的任务类型。
- 速度劣势不否定质量优势：复合体在延迟维度（TPS）得分可能较低，但在 LogicDepth、CrossVerify、Accuracy 维度可能显著优于纯AI，综合评分仍具竞争力。
- 复合体中人类角色定位为"逻辑发起者与质量仲裁者"，AI集群定位为"执行与穷举引擎"，二者分工在 `position.json` 的 `required_logic_level` 中体现。
- 复合体参赛不豁免防泄露要求：人类提出的逻辑框架不得包含测试集原题或答案。

### 标定方法

- 使用已知正确答案的测试集确定各模型的能力边界。
- 测试用例来源：历史迭代中人工确认正确的输出、外部标准数据集（MMLU子集、GSM8K子集、自定义逻辑链题目）。
- 不使用模型自我评分（避免自评偏差）。
- 每个测试用例附带 `expected_output` 和 `scoring_rubric`（评分细则），确保评分可复现。
- 复合体参赛用例额外附带 `human_logic_seed`（人类逻辑种子，用于区分人类贡献与AI执行贡献的评分归属）。

### 测试集更新触发条件

| 触发事件 | 动作 |
|----------|------|
| 新模型发布 | 将新模型纳入候选池，跑全量测试集 |
| 新实测数据进入 | 提取新数据中的典型任务模式，追加为测试用例 |
| 现有模型性能下滑超过阈值 | 触发回归测试，定位退化原因，更新测试集覆盖该退化模式 |
| 文明OS节点结构变更 | 新增/修改节点时，同步更新对应 position.json 和测试用例 |
| 季度定期审查 | 清理过时用例，补充新任务类型，执行语义等价改写（防泄露） |
| 检测到答案泄露迹象 | 立即轮换受影响用例子集，启动溯源分析，更新混淆策略 |
| 复合体参赛模式调整 | 更新 `human_logic_seed` 相关用例结构与评分归属规则 |
