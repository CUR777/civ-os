# 节点5：交叉核验架构

【中期·条件性推演】该架构依赖多个同档不同模型同时可用，当前阶段由单一模型（Qwen 3.8 flash）完成全部迭代，交叉核验为设计蓝图。

## 形式化定义

采用3层核验机制保障输出质量：

- **Layer 1：** Model_A(node) → result_A，产出初稿。
- **Layer 2：** Model_B(node) → result_B（Model_B ≠ Model_A，同档位不同模型），计算与Layer 1的偏离分数。
  - Score = divergence(result_A, result_B)
  - 若 Score < θ_low → 一致采纳（取均值或随机选一）。
  - 若 θ_low ≤ Score < θ_high → 轻微分歧，标记观察，下轮复核。
  - 若 Score ≥ θ_high → 重大分歧，升级至Layer 3。
- **Layer 3：** Model_C(node) → result_C（更高档位模型裁决分歧），产出最终版本。

**成本预估：** 约95%节点在Layer 1+2通过，5%需Layer 3裁决。总计算成本约为单模型基础的8.25倍（2倍基础 + 5% × 125倍高档模型）。

**设计理由：** 同档不同模型的交叉核验可捕获单模型系统性偏差；双阈值分层（θ_low / θ_high）区分一致、轻微分歧与重大分歧，避免对微小噪声过度升级；升级机制确保极端分歧不丢失，同时避免全量高成本处理。

## 增量更新机制（与交叉核验互补）

新数据进入时的处理流程：

> 新数据进入 → 识别受影响节点 → 局部重新推理 → 与相邻节点比对 → 传播更新到依赖链 → 全局一致性检查 → 版本标记 → 发布

三种策略并行：

1. **依赖图传播：** 新数据只沿依赖链传播，复杂度 O(k)，k = 链长度。
2. **分层聚合：** 底层更新聚合为中层摘要 → 中层变化则传播到高层。
3. **定期全量校对：** 每 N 轮增量后做一次全量比对，修正累积偏差。

【中期·条件性推演】当前单文件 iterate.py 为全量处理，增量模式依赖节点间依赖图数据结构，待多节点架构落地后实施。

## 子节点05-01：Layer1~3校验的完整形式化规范

### 形式化定义

| 层级 | 输入 | 输出 | 模型要求 |
|------|------|------|----------|
| Layer 1 | node（待核验节点内容） | result_A | Model_A（基准模型） |
| Layer 2 | node | result_B | Model_B（同档位、不同模型，Model_B ≠ Model_A） |
| Layer 3 | node + result_A + result_B + divergence报告 | result_C（最终裁决） | Model_C（更高档位模型） |

### 偏离分数计算与阈值判定

```
Score = divergence(result_A, result_B)
```

- **Score < θ_low：** 一致采纳。策略：取两结果语义均值，或随机选取其一。
- **θ_low ≤ Score < θ_high：** 轻微分歧。标记为"观察态"，下一迭代周期复核；不触发升级。
- **Score ≥ θ_high：** 重大分歧。升级至 Layer 3，由更高档位模型裁决，产出最终版本。

### 成本分析

- 预估分布：约 95% 节点在 Layer 1 + Layer 2 通过，约 5% 需 Layer 3 裁决。
- Layer 3 单次成本约为 Layer 1 的 125 倍（高档模型推理开销）。
- 总等效成本 ≈ 2 × 基础成本 + 5% × 125 × 基础成本 = 8.25 × 基础成本。
- 成本可控性：通过调高 θ_high 可减少 Layer 3 触发频率，但需平衡漏检风险。

### θ阈值标定方法

【中期·条件性推演】

采用元分析法（meta-analysis calibration）：

1. 构建已知正确答案的测试集（golden set），覆盖各节点类型。
2. 对测试集执行 Layer 1 + Layer 2，记录实际 Score 分布。
3. 以"人工判定为一致/轻微分歧/重大分歧"为标签，拟合 θ_low 和 θ_high 的最优分割点。
4. 初始标定后，每 10 轮迭代用新增 golden set 样本重新校准，防止阈值漂移。

## 子节点05-02：当前单模型环境下的替代质量保证方案

### 背景约束

当前阶段仅有单一模型（Qwen 3.8 flash）可用，无法执行真正的多模型交叉核验。以下方案为单模型环境下的近似替代策略。

### 方案1：Temperature 变化对比

- 同一 node 分别以 temperature = 0.1（确定性输出）和 temperature = 0.6（创造性输出）各生成一次。
- 比较两次输出的语义一致性：若核心结论一致，视为通过；若出现逻辑矛盾，标记为需人工复核。
- 局限：同一模型的不同采样参数仍共享训练偏差，无法捕获系统性盲区。

### 方案2：系统提示词变体对比

- 同一 node 分别使用"精简版系统提示词"（仅保留公理约束）和"详细版系统提示词"（含完整上下文与示例）各生成一次。
- 比较两次输出：若详细版引入了精简版未覆盖的关键逻辑，标记为潜在遗漏。
- 局限：提示词工程差异可能引入噪声，需结合方案1联合判断。

### 方案3：分段后内部一致性检测

- 将输出按段落/章节切分。
- 检查跨段落的引用一致性（如"如前所述"指向的内容是否确实存在且匹配）。
- 检查逻辑链完整性（前提→推理→结论是否每段自洽，段间衔接是否无矛盾）。
- 发现不一致时，定位冲突段落对，标记为需修正。

### 当前实际方案【当前阶段·已实现】

单次全量处理 + 自动校验，校验项包括：

- 公理区完整性检查（三条公理文字是否原封不动存在）。
- 内容非空检查（输出体积 > 0）。
- 结构完整性检查（标题层级、必要节是否存在）。

### 人工抽检触发条件

以下任一条件满足时，触发人工抽检：

1. 自动校验失败（公理区缺失、内容为空等）。
2. 输出体积异常：小于原文 50%（疑似截断）或大于原文 200%（疑似冗余膨胀）。
3. 首次对某节点进行分段迭代（无历史基线可比）。

## 子节点05-03：增量更新的依赖图设计

### 依赖关系表示

每个节点维护两类依赖信息：

- **cross_refs 字段（显式互引）：** 节点主动声明"我引用了哪些其他节点"。例如节点5声明 cross_refs = [节点1, 节点3]，表示其内容依赖节点1和节点3的结论。
- **反向索引（被引用关系）：** 由系统自动维护，记录"哪些节点引用了我"。当节点X被修改时，通过反向索引快速定位所有下游受影响节点。

### 传播算法

```
新数据进入
  → 识别变化节点（直接修改的节点集合 S₀）
  → 沿 cross_refs 正向传播：S₁ = {n | n.cross_refs ∩ S₀ ≠ ∅}
  → 递归：S_{i+1} = {n | n.cross_refs ∩ S_i ≠ ∅}，直到 S_{i+1} = ∅
  → 对 S₀ ∪ S₁ ∪ ... ∪ S_k 中每个节点执行局部重新推理
  → 全局一致性检查
  → 版本标记 → 发布
```

### 复杂度分析

- 传播复杂度：O(k)，k = 依赖链最大长度。
- 对比全量处理复杂度：O(N)，N = 节点总数。
- 当 k ≪ N 时（典型情况），增量模式节省大量计算资源。
- 最坏情况：若所有节点形成单一长链（k = N），退化为全量处理，此时触发全量校对更经济。

### 触发全量校对的条件

【中期·条件性推演】

以下任一条件满足时，放弃增量模式，执行全量比对：

1. **周期性触发：** 每 50 轮增量更新后，强制执行一次全量校对，修正累积偏差。
2. **异常触发：** 增量传播过程中发现跨链逻辑不一致（如节点A的结论与节点B的结论矛盾，且二者不在同一传播链上）。
3. **结构变更触发：** 节点间依赖关系发生拓扑变化（新增/删除节点、cross_refs 字段大幅修改）时，立即全量校对。

### 当前状态

【中期·条件性推演】当前单文件 iterate.py 为全量处理模式，增量依赖图尚未落地。待多节点架构（节点间以独立文件/数据结构存储）实施后，启用本设计。
