### 核心机制

- **Git hash 保证数据完整性：** 每次 commit 生成 SHA256 指纹，任何内容篡改必然改变哈希值，使篡改行为在数学层面不可隐藏。
- **Append-only 机制：** 禁止 force push 和 rebase，所有历史永久保留且可审计。任何修改以新 commit 形式追加，不覆盖、不删除既有记录。
- **GitHub Protected Branch（建议启用）：** 任何推送需通过智能体校验（检查是否违反公理Ⅰ~Ⅲ），未通过校验的提交自动拒绝合并。
- **GitHub OAuth 身份验证：** 目前仅原作者（CUR777）拥有 push 权限；外部贡献者通过 Fork + Pull Request 模式提交，修改在隔离分支中运行，不直接影响主仓库。

### 局限性

当前架构依赖 GitHub 平台安全，无法抵御平台层面的攻击（如平台被入侵、内部人员越权操作等）。此局限性在初代阶段可接受，中期升级路径（子节点12-02）将引入去中心化验证机制以消除此单点依赖。
