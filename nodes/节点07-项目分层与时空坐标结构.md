# 文明OS

## 节点7：项目分层与时空坐标结构

> created_at: 2026-09-26T21:34:02.806Z
V20260927053410+


**版本：v0.1.2**

【当前阶段·已实现】

**主结构（项目层级分解）：**

```
宇宙觉醒
 └─ 文明阶段
     └─ 技术领域
         └─ 项目
             └─ 子任务
                 └─ 步骤
```

**时空坐标附加：** 每个节点附带时空坐标（时间范围 + 抽象空间范围），坐标允许重叠。

**空间描述规范：** 使用范围性描述（如"太阳系内""银河系悬臂""可观测宇宙"），不使用具体地点坐标。

**层级截断规则：** 顶层固定保持宇宙觉醒级抽象水平；下层按需截断或扩展细节。

---

**节点标准数据格式（JSON Schema 规范）：**

每个节点的结构化表示应包含以下字段：

```json
{
  "id": "string (uuid)",
  "layer": "integer (0=顶层宇宙觉醒, 数字越大越底层)",
  "parent_id": "string|null (上层节点id, 根节点为null)",
  "title": "string (节点名称)",
  "description": "string (~100 token文本描述)",
  "time_range": {
    "start_year": "float",
    "end_year": "float"
  },
  "space_scope": "string (抽象空间范围描述, 如'太阳系内', 非具体地点, 允许重叠)",
  "status": "enum: placeholder | draft | verified | outdated",
  "last_updated": "string (ISO-8601日期)",
  "model_tier": "enum: 1B | 3B | 7B | 14B | 32B | 125B | cluster",
  "children_count": "integer",
  "cross_refs": "array[string] (关联节点id列表, 节点间互引)",
  "confidence": "float (0.0~1.0)",
  "data_source": "enum: inference | literature | measured",
  "iteration_version": "string (当前迭代版本号)"
}
```

**字段说明：**

| 字段 | 用途 |
|------|------|
| `id` | 全局唯一标识，用于 `parent_id` 和 `cross_refs` 的引用锚点 |
| `layer` | 编码层级深度，支持按层过滤与截断渲染 |
| `parent_id` | 构建树形结构；根节点（宇宙觉醒）为 `null` |
| `description` | 约100 token的摘要，供上层节点聚合展示 |
| `time_range` | 浮点年份，支持跨尺度（如 13.8e9 ~ 0 表示宇宙史） |
| `space_scope` | 范围性描述，允许重叠，不绑定具体坐标 |
| `status` | 生命周期状态：placeholder→draft→verified→outdated |
| `model_tier` | 处理该节点推荐的模型层级，指导计算资源分配 |
| `cross_refs` | 非树形关联（如"量子计算"节点引用"材料科学"节点） |
| `confidence` | 反映 `data_source` 与推理链的可靠程度 |
| `data_source` | 区分知识来源，影响 `confidence` 的合理上限 |

**实施阶段说明：** 当前纯文本阶段此 schema 作为设计规范文档保留；后续结构化阶段将每个节点文件的元数据区按此格式实现。

### 子节点07-01：节点 Schema 14 字段详细说明

**设计目的：** 为每个字段提供生成规则、取值约束与当前阶段实施边界，确保纯文本阶段与未来结构化阶段平滑过渡。

| 字段 | 类型 | 生成规则与约束 |
|------|------|----------------|
| `id` | uuid | 唯一标识。生成规则：时间戳 + 随机串拼接后哈希，保证全局唯一且可追溯创建时间 |
| `layer` | int | 层级深度。0 = 顶层宇宙觉醒；数字越大越底层、越具体。与主结构6层对应（0~5） |
| `parent_id` | uuid / null | 上层节点 id，构建树形结构；根节点（宇宙觉醒）为 `null` |
| `title` | string | 节点名称，建议 30 字以内，保持语义自明 |
| `description` | string (~100 token) | 核心内容摘要，供 AI 快速理解节点定位与上下文，不重复 title |
| `time_range` | {start_year, end_year} | float 型年份。负数 = 公元前；科学计数法表示远期（如 1e12 表示万亿年后） |
| `space_scope` | string | 抽象范围描述，如"太阳系内""地球陆地""东亚地区"。允许重叠，不绑定具体坐标 |
| `status` | enum | `placeholder`（占位待填）/ `draft`（草稿）/ `verified`（已验证）/ `outdated`（需更新） |
| `last_updated` | ISO-8601 | 最近一次内容变更日期，格式 `YYYY-MM-DD` |
| `model_tier` | enum | 1B / 3B / 7B / 14B / 32B / 125B / cluster。推荐处理此节点的模型层级，指导计算资源分配 |
| `children_count` | int | 直接子节点数量，用于渲染时判断是否可展开 |
| `cross_refs` | [uuid] | 显式关联节点列表，用于依赖图传播与非树形引用 |
| `confidence` | float (0.0~1.0) | 内容置信度。推理 ≈ 0.5~0.7；文献支撑 ≈ 0.7~0.9；实测 ≈ 0.9+ |
| `data_source` | enum | `inference` / `literature` / `measured`，主要来源类型，影响 confidence 合理上限 |
| `iteration_version` | int | 该节点经历的迭代轮次计数，每次实质内容变更 +1 |

**当前阶段实施边界：** 纯文本阶段仅手动维护 `title` + `description` + `time_range` 三个字段；其余字段为规范备存，待结构化阶段自动填充。

### 子节点07-02：从宇宙觉醒到可执行步骤的典型拆解示例

**示例主题：** 清洁能源系统

展示完整 6 层拆解链，体现粒度控制原则：

| 层级 | 节点 | 内容 | 关键属性 |
|------|------|------|----------|
| 层0（宇宙觉醒） | 宇宙物质-能量最优利用 | 方向性目标，不可执行 | layer=0, parent_id=null |
| 层1（文明阶段） | 地球文明能源系统优化 | 文明尺度目标 | time_range: 2000~2100, space_scope: "地球" |
| 层2（技术领域） | 太阳能技术路线 | 技术路径选择 | space_scope: "全球陆地+海面" |
| 层3（具体项目） | 钙钛矿太阳能电池效率提升 | 可立项、可追踪 | confidence=0.85, data_source=literature |
| 层4（子任务） | 稳定性问题攻关 | 有明确技术瓶颈 | status=draft |
| 层5（可执行步骤） | 合成新型封装材料 | 有明确主体/时间/方法 | model_tier=7B, time_range: 2025~2027 |

**粒度控制原则：**

- 顶层（层0~1）= 方向性描述，不可直接执行，用于对齐全局目标
- 中间层（层2~3）= 可立项、可追踪，有明确技术/项目边界
- 底层（层4~5）= 可执行，必须包含明确主体、时间范围、方法/产出物

**拆解终止条件：** 当某步骤已满足"谁 + 何时 + 做什么 + 产出什么"四要素时，不再向下拆分。

### 子节点07-03：空间坐标系设计原则与重叠处理

**为何使用抽象范围而非具体地点坐标：**

1. **精度匹配：** 避免坐标系精度（如经纬度小数点后6位）与内容描述精度（如"太阳系内"）不匹配，减少无意义精度伪象
2. **抗政治地理变化：** 国家边界、行政区划随时间演变；抽象范围（如"东亚地区"）在节点生命周期内保持稳定，减少因政治地理变化导致的节点失效
3. **跨尺度兼容：** 同一字段可表达"可观测宇宙"到"某实验室"，无需切换坐标系统

**允许重叠的逻辑：**

- 不同维度的项目可以发生在同一空间，互不冲突（例：太阳能项目与生态恢复项目均覆盖"全球陆地"）
- 重叠是常态而非异常，不触发合并

**重叠时的处理规则：**

- 通过 `cross_refs` 建立空间关联，不合并节点
- 渲染时按 `layer` 过滤，同层同空间节点并列展示
- 冲突检测仅在 `parent_id` 相同且 `time_range` 重叠且 `space_scope` 重叠时触发，提示人工审核

**空间粒度匹配原则：**

- 同层级节点应有相似的时空粒度
- 禁止同层出现"宇宙"与"某市"并列（应通过增加中间层级解决）
- 若发现粒度不匹配，优先调整 `layer` 值而非修改 `space_scope`

### 子节点07-04：分层决策的版本历史保留（认知考古学原则）

**核心主张：** 项目分层结构在迭代过程中，每一层的历史版本必须保留，而非仅保留当前版本。

**逻辑依据：**

- 旧的分层决策本身携带信息：为何当时选择该分层方式？当时的技术/认知约束是什么？后来为何改变？
- 删除旧版本等同于抹除决策推理链，使后续迭代失去"为何不采用旧方案"的参照基准
- 这是文明OS「只增不删」原则在项目分层维度的具体体现

**实施规则：**

| 操作 | 处理方式 |
|------|----------|
| 层级重新划分（如将层2拆为2a/2b） | 保留原层2节点，标记 `status: outdated`；新增2a/2b节点，`parent_id` 指向原层2 |
| 节点归属变更（如某项目从层3移至层4） | 保留原位置记录（以 `cross_refs` 或注释形式），新位置正常创建 |
| 层级数量调整（如6层→7层） | 保留原6层结构快照，新结构以新版本号记录，两者通过 `iteration_version` 关联 |

**元数据扩展（待结构化阶段实现）：**

```json
{
  "layer_history": [
    {
      "version": "v0.1.0",
      "structure_snapshot": "6层",
      "change_reason": "string (为何变更)",
      "context_constraints": "string (当时的技术/认知约束)"
    }
  ]
}
```

**当前阶段实施边界：** 纯文本阶段以文件内注释或 `outdated` 标记保留旧结构描述；结构化阶段由 `layer_history` 字段自动维护。

### 子节点07-05：抽象→具象映射协议

**问题陈述：** 顶层抽象节点（如"宇宙觉醒""全局最优"）若缺乏向下映射路径，将退化为不可验证的口号，丧失指导意义。

**映射协议定义：** 每个层0~1的抽象节点，必须附带一条具象化映射路径，包含以下三要素：

| 要素 | 内容 | 示例（以"宇宙觉醒"为例） |
|------|------|--------------------------|
| **当前部分实现** | 该抽象在当前技术条件下已被部分实现的具体形态 | "人类已建立可观测宇宙模型、核聚变实验装置、全球互联网信息层" |
| **实现程度衡量指标** | 可量化或可判定的进度度量 | "信息整合度（已联网知识/可观测宇宙可编码信息）""能量利用效率（当前/理论上限）" |
| **映射锚点** | 指向层2~5中具体节点的 `cross_refs` | 指向"全球互联网基础设施""ITER核聚变项目"等节点 |

**协议约束：**

1. **非穷尽性：** 映射路径不要求覆盖抽象概念的全部内涵，仅要求存在至少一条可追踪的具象锚点
2. **时效性：** 映射路径随技术发展更新；当某锚点节点 `status` 变为 `verified` 或 `outdated` 时，触发映射路径复审
3. **防空洞检测：** 若某抽象节点在连续3次迭代中无法生成有效映射锚点，标记为 `status: draft` 并记录阻塞原因（如"等待进一步技术发展后重新评估"），但节点本身不删除、不关闭

**与粒度控制原则的关系：**

- 粒度控制原则（子节点07-02）规定"顶层为方向性描述，不可直接执行"
- 映射协议补充规定"不可执行≠不可映射"——顶层虽不可直接执行，但必须存在向下可追踪的具象化路径
- 二者共同确保：顶层提供方向，映射提供可验证性，底层提供可执行性
