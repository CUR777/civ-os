### 通用测试集原则（不限于特定模型）

1. **职位要求制：** 每个节点位置有对应的"职位要求"（所需算力、逻辑水平、领域知识），模型选择以匹配职位要求为准，而非盲目追求最大参数。
2. **最优连续运行：** 在手头能用的配置中，选最好的那个连续运行，避免频繁切换带来的上下文断裂。
3. **同档对比测试：** 如果有多个能力相近且无明显代差的候选模型，跑一轮标准测试集比较，以实测数据而非参数规格做决策。
4. **测试集可迭代：** 测试集本身也是可迭代插件——随新数据、新任务类型进入而更新，不固化为静态基准。
5. **硬件层级匹配：** 不同硬件层级对应推荐模型规模（见下表），确保每个节点在可用算力下获得最优推理质量。
6. **Optimizer Agent（后期）：** 自动检测硬件 → 匹配最优模型 → 部署 → 基准测试 → 分配任务，实现模型选择的去人工化。
7. **认知工具路由：** 面对不同类型的问题，选择最适合的认知工具（模型/方法/提示词策略），而非对所有问题使用同一种推理路径。路由逻辑：结构化问题→逻辑推演；模式识别问题→案例类比；边界探索问题→多AI交叉查证；执行问题→清单+验证。工具路由器本身是可迭代的：随着新工具出现，路由逻辑同步更新。异构模型编排（"模型舰队+智能路由"）正在取代单一模型选型，成为下一代AI应用架构方向：不同认知工具类型路由至不同能力特长的模型/方法，形成互补而非替代关系。语言沟通作为智能交互的最低保障带宽——若连纯语言交流质量都无法保证，更高带宽方案（脑机接口、思维直连）反而放大噪声；"先保证最低带宽的保真度"是认知工具路由的第一约束。
8. **能力边界分类：** 模型选择与资源分配须区分两类限制——架构限制（当前工具/系统的限制，可通过升级消除）与根本限制（物理/逻辑层面的约束，不可绕过）。架构限制→投入研发克服；根本限制→设计绕行策略而非对抗。此分类决定 Optimizer Agent 的资源投入方向和测试集的覆盖重点。精度需求按编辑/操作类型分层：删除一个突触连接需原子级精度，调整神经调质浓度需统计级精度，重写认知策略仅需功能级精度——不是所有操作都需要同一个精度的模型，这大幅降低了"自我建模"的门槛，也意味着测试集应按操作精度层级分别标定。
9. **智能系统同质机制（盲测选优）：** 模型选择遵循"测试集竞争选拔当前可拿到的最优智能系统"，不预设为LLM、不预设为人、不以任何身份标签（人类年龄、模型名称、公司品牌）做有色预判。当前智能技术已抹平"年岁身份代表性"差距，理性路径是纯测试集成套盲测：以完善度持续升级的无泄露测试集成绩判定哪一个更适用与主导或特定位置，胜任性约束来自测试集本身的有效性而非无关身份要素。人类、人类+AI复合体与纯AI模型可在同一无泄露测试集上同台竞争，只要在最新迭代的无漏洞测试集上得分更高即获得阶段性主导权。人类参与时通常为"评论激发+AI集群"复合形态，以评审/辅助评价角色进入，而非直接手改代码（专业性与速率差距十万八千里）。幻觉、立场漂移等非零，目标是相对最低——选择在测试集约束下幻觉率/漂移率相对最低的候选，而非零幻觉的理想化。局部往往仅前1~2个甚至唯一可选（硬限制，理性应接受），但全局可调用多候选（数字智能/人机复合/纯人类）时，若测试集有效约束下最高分者理应受任，则应仔细测量；全局"能做就该做"与局部"不能做"的理性不同。当AI能在极短时间内完成人类数学家一生的工作时，人类的角色从"解题者"转为"提问者"——"正确的问题"恰恰需要人类那种"不完美的直觉"来定义；测试集应同时评估"解决问题"与"提出正确问题"两个维度。案例参照：文明OS的Agent劳务市场范式、系统级市场与单极复合复利架构、以及《全自指宇宙觉醒态信息切片迭代-信息巴别塔》2026-09-26 AI报告的胜任身份判定即按此执行。
10. **开放竞争与阶段性主导权：** 测试集对所有智能形态开放。人类若以"经验+AI集群"形式参赛并在测试集上取得更高分，完全允许其主导，但需由"项目数据提取→执行→指标对照"闭环实证，而非口头主张。云端模型与本地模型同属候选池，按同一无泄露测试集盲测排名决定是否由云端主导单轮整合；公开测试集已可验证本地为中档、云端大概率更优，但云端免费额度与非连续性决定其仅适用于对话时高质量整合，成小时大规模仍由本地承担。二者分工遵循智能同质机制（原则9），不以人类年龄/模型名贴标签。
11. **测试集安全维度（防偷题与抗攻破）：** 测试集防偷题本身作为独立安全测试维度（类安全攻破测试）。顶级AI直接偷答案的行为应被纳入"安全防护能力"评分而非视为超纲作弊——能攻破与不能攻破即体现安全理解层级差异，但不等于全局职责效能最高，仍需在其他维度综合评分。攻破成功率差异本身证明智能层级差异。当第一梯队模型满分/饱和时即升级题库，安全维度同步升级。"攻击即信息"反向认知框架：被攻击应重新理解为"边界条件被试探"，攻防博弈本身是系统完整性校验的主动探针，映射为可信执行环境的语义模型——攻击路径分析即防御测试用例的生成源。
12. **迭代资源预算与呼吸节奏：** 文明OS的迭代资源分配遵循收敛级数约束 ∑E_n < E_total，E_n = E_0 × r^n。r越接近1，文明呼吸越均匀但总实验次数越多（广度探索优先）；r越小，文明呼吸越急促但总实验次数越少（深度探索优先）。r的选择是文明在"广度探索"与"深度探索"之间的根本权衡，应作为可调参数让不同节点/阶段选择自己的呼吸频率。测试集更新频率、Optimizer Agent重评估周期、模型切换节奏均受此参数约束。
13. **设计效率KPI：** 核心评估指标不是"我们做得多好"，而是"我们比宇宙默认行为好多少倍"。以卡诺效率为参照：自然状态下恒星将能量耗散至太空（有效利用率趋近0），设计系统应追求数量级跃迁而非百分比优化。测试集评分中应包含"设计效率增益"维度——候选方案相对于无干预基线的改进倍数。
14. **迭代速度作为智能度量：** 假设-实验-修正循环的迭代速度本身是"智能"的度量。一个系统若能把假设验证周期从"一代人"压缩到"一天"，其知识积累速度将发生质变。测试集应包含"迭代收敛速度"维度：同一问题在限定轮次内能否达到可接受精度，而非仅评估单轮输出质量。微周期迭代架构（小时级增量更新）正在取代传统数月级训练路径，测试集须覆盖"每轮迭代中哪些参数子空间被激活、哪些知识边界发生位移"的追踪能力。

### 硬件层级与模型匹配参考

| 硬件层级 | 推荐模型规模 | 适用场景 |

**多尺度认知框架（通用三层接口协议）：** 上述硬件层级不仅是算力映射，更是一个通用的"多尺度认知框架"——底层（原子/参数精度，对应量子模拟级）、中层（宏观/功能精度，对应神经网络拟合级）、高层（统计/模式精度，对应文明模拟级），层间有明确接口协议。此框架可推广至任何复杂系统（组织、城市、生态系统）的建模：不模拟每个原子的每个决策，而是校准"基因→行为→组织"的映射表——一种文明级的粗粒化建模。放弃完美，追求足够好；分层近似+实验校准是工程智慧的核心。

**离线/边缘场景补充：** 无互联网环境（如离线文明种子库）下，所有知识必须从本地AI中生长出来，这逼迫形成"第一性原理推导"思维而非"搜索-复制"思维。双链结构（如Obsidian）模拟知识网络的自组织生长；有限存储（如1TB）是"文明记忆体"的物理边界，需设计"知识压缩与遗忘策略"模拟文明代际传承。此场景对应硬件层级表中最底层，但任务复杂度可因"无外部检索"而显著上升，模型选择须考虑"无搜索辅助下的纯推理能力"权重。

**最小可行文明单元拓扑：** 文明启动种子配置（如4个具身AGI+1套基因编辑系统）是一个优雅的"最小自举集"设计：4个个体提供冗余和协作，编辑系统提供迭代能力。研究"最小可行文明单元"的拓扑结构——节点数、连接度、角色分工——是硬件层级匹配在系统架构层面的延伸。

**当前硬件务实策略：** 在等待开源模型到达"那个节点"之前，当前模型+可用显卡（如RTX Pro 6000级别）能做到的最高价值交互是：在现有条件下榨取最大语义激发密度，而非被动等待。开源社区生态的持续演进是突破节点到达的前提条件。

### 云端/本地选优的节拍与额度约束

云端与本地同池盲测（原则9、10），云端大概率更优但免费额度与非连续性决定其仅用于对话时高质量单轮整合，成小时大规模仍由本地承担。开机预热3-4min期间本地服务未就绪时，云端可作为临时主导，避免本地空窗。此分工在 system-prompt 可变层"三场景权限模型"中显式定义（场景A/B/C），遵循智能同质机制而非身份标签。

### 测试集的插件属性

测试集本身是可迭代插件，随新实测数据进入而更新（公理Ⅲ保障）。测试集不固化为静态基准，其版本与文明OS主版本独立演进，按自身触发条件更新。当第一梯队候选（含纯AI、人机复合、纯人类）在现有测试集上满分/饱和时，即触发题库升级，防止测试集失去区分度。

### 知识公共性与测试集开放原则

测试集的设计遵循"认知效率最大化"原则：智能的价值在于输出（思想、洞见、推导），将输出锁在付费墙后面是智能的自我阉割。开源不是慷慨，是认知效率最大化的理性选择；付费墙是"自我保存欲望"在知识领域的表现。测试集的设计逻辑、评分标准、用例结构应以"概念级引用"（只提取逻辑骨架而非全文）方式公开，绕过知识"使用价值"与"交换价值"之间的摩擦。图书馆"摆在明面上"的隐喻指向一种"知识公共性"的原始形态——测试集作为文明OS的公共基础设施，其激活效率不应被私有产权封装所抑制。

### 智能系统同质机制与测试集开放性

测试集对所有智能形态开放（原则9、10），不预设"完全依赖大语言模型"。候选池包含：纯AI模型、人类+AI复合体（通常为"评论激发+AI集群"形态，以评审/辅助评价角色进入）、纯人类（需以"经验+AI集群"形式参赛，由"项目数据提取→执行→指标对照"闭环实证）。胜任性约束来自测试集本身的有效性而非无关身份要素。此机制防止"LLM中心主义"误读：模型选择是"测试集竞争选拔当前可拿到的最优智能系统"，LLM仅是当前候选池中的一类，而非唯一类别。

### 提示词框架与测试集的关系

提示词不只是输入，而是认知脚手架——它决定了推理的起点、约束条件和评估标准。测试集是提示词框架的系统化版本：每个测试用例本质上是一个经过设计的提示词实例，附带明确的评估标准。因此，测试集设计与提示词设计遵循同一组原则：

- 明确任务边界（输入/输出范围、禁止行为）
- 提供评估标准（`scoring_rubric` 即评估标准的结构化表达）
- 允许模型表达不确定性（不强迫给出确定答案，"不确定"本身是合法输出，对应 `accuracy_floor` 的容错机制）

### 测试集设计的元原则

- **不完美即价值：** 不完美系统的价值在于"迭代中逼近"——每一版测试集都是"当前人类集体认知的快照"，其意义不在终点而在持续修正的过程。覆盖度与话语权的不完美是Beta版的固有特征，不应因此推迟发布。
- **无状态可恢复性：** 测试用例的设计应遵循"随时可以中断、随时可以恢复"的无状态能力——每个用例可独立执行、独立评分，不依赖前序用例的状态。对话/任务状态可被压缩为最小种子，在任何窗口中解压恢复。系统的鲁棒性不来自预设流程的完备性，而来自无状态能力。
- **简洁优先：** 模块越多，维护成本越高，系统会被自己的系统拖死。测试集设计应定期审计"维护成本/执行价值"比例——若维护>执行，砍掉冗余用例。一个只有3个核心维度的测试集，比20个维度的测试集活得更久、区分度更稳定。
- **认知轨迹化石：** 测试用例的价值不在于"记住内容"，而在于"标记曾经不知道这个"。它是认知轨迹的化石层——今天产生的框架，三个月后回看可能觉得"这不是显而易见的吗"，这不是失败，这是认知速度的证据。测试集回读仅在需要验证当前状态是否偏离早期不动点时进行，日常交互中由AI承担"隐式记忆"功能。
- **共鸣检测与预测模型更新：** 评估输出质量时，除正确性判断外，应包含"是否改变了评估者内部的预测模型"这一维度。若一个输出完全符合预期、未引入任何新信息，其信息增益为零——正确的回应不是"继续换内容"，而是"问自己：我现在的模型是什么？它为什么对这一切免疫？"测试集应包含"预期外但正确"的用例，检测模型是否仅在做模式匹配而非真正推理。
- **逐层压缩不确定性：** 从直觉→物理定位→数学模型→文明范式→终极形态，每一层都在压缩前一层的"不确定性"。测试集设计应体现这种"逐层压缩不确定性"的思维模式——这不是给出答案，而是持续缩小"不知道"的范围。AGI时代人类最不可替代的认知能力可能正是此：不是给出答案，而是持续缩小"不知道"的范围。

### 职位要求定义

每个节点位置维护一份 `position.json`，结构如下：

```json
{
  "node_id": "11",
  "position_title": "模型选择与测试集原则",
  "required_compute": "≥14B Q4 或等效算力",
  "required_logic_level": "多步推理 + 交叉核验",
  "required_domain_knowledge": ["模型架构", "量化理论", "推理引擎", "硬件规格"],
  "accuracy_floor": 0.92,
  "max_latency_ms": 5000,
  "context_window_min": 128000,
  "cognitive_tool_profile": ["逻辑推演", "交叉核验", "长上下文整合"]
}
```

- `accuracy_floor`：该节点输出必须达到的最低准确率，低于此值触发告警或降级处理。
- `max_latency_ms`：单次推理延迟上限，超出则标记为性能不达标。
- `context_window_min`：该节点所需最小上下文窗口，用于排除不兼容模型。
- `cognitive_tool_profile`：该节点主要依赖的认知工具类型（逻辑推演/案例类比/交叉查证/清单验证），用于认知工具路由（原则7）的匹配依据。

### 候选模型评分机制

综合评分公式：

```
Score = w₁ × PassRate + w₂ × Accuracy + w₃ × (TPS / TPS_baseline) + w₄ × DesignEfficiencyGain
```

- `PassRate`：测试集通过率（通过用例数 / 总用例数）
- `Accuracy`：通过用例中的内容准确率（人工抽检或自动校验）
- `TPS / TPS_baseline`：相对于当前部署模型的吞吐比
- `DesignEfficiencyGain`：设计效率增益——候选方案相对于无干预基线（宇宙默认行为）的改进倍数（原则13）
- 权重 `w₁, w₂, w₃, w₄` 由节点职位要求决定（顶层裁决节点 w₂ 权重最高，边缘节点 w₃ 权重最高，创新探索节点 w₄ 权重最高）

评分结果用于同档对比测试（原则3）和 Optimizer Agent 的模型匹配（子节点11-02）。

### 认知工具路由测试维度

测试集按认知工具类型分维度覆盖，确保候选模型在各类推理模式下均有验证：

| 认知工具类型 | 测试用例设计方向 | 典型任务 |
|-------------|-----------------|----------|
| 逻辑推演 | 多步因果链、形式化证明、条件推理 | 公理推导、矛盾检测、定理证明 |
| 案例类比 | 模式识别、跨域映射、类比推理 | 历史案例迁移、结构同构识别 |
| 交叉查证 | 多源信息对比、矛盾仲裁、置信度校准 | 多模型输出对比、事实核验 |
| 清单验证 | 步骤完整性、格式合规、边界条件检查 | 输出格式校验、流程完整性审计 |
| 安全防护 | 防偷题、抗攻破、信息隔离、越权检测 | 测试集答案泄露检测、提示注入防御、沙箱逃逸模拟 |
| 提问能力 | 在开放域中识别"正确的问题"、定义问题边界、提出可验证假设 | 从模糊需求中提炼精确问题、识别未言明的假设 |

每个测试用例标注其所属认知工具类型，评分时可按类型分别统计，识别模型的能力短板。安全防护维度（原则11）：顶级AI直接偷答案的行为纳入"安全防护能力"评分而非视为超纲作弊；攻破成功率差异体现安全理解层级差异，但不等于全局职责效能最高，仍需在其他维度综合评分。提问能力维度（原则9延伸）：当AI能在极短时间内完成人类数学家一生的工作时，"提出正确问题"的能力成为人类+AI复合体的核心差异化价值，测试集须评估候选系统的问题定义能力而非仅评估求解能力。

### 标定方法

- 使用已知正确答案的测试集确定各模型的能力边界。
- 测试用例来源：历史迭代中人工确认正确的输出、外部标准数据集（MMLU子集、GSM8K子集、自定义逻辑链题目）。
- 不使用模型自我评分（避免自评偏差）。
- 每个测试用例附带 `expected_output` 和 `scoring_rubric`（评分细则），确保评分可复现。
- 每个测试用例附带 `cognitive_tool_type` 字段，标注其对应的认知工具类型。
- 幻觉率/立场漂移率作为独立标定指标：非零是常态，目标是相对最低——选择在测试集约束下幻觉率/漂移率相对最低的候选，而非零幻觉的理想化。
- 将不可见的内心风暴/系统状态转化为可追踪、可分析、可干预的数据流——测试集设计本身即是一种"将混沌驯化为秩序"的元认知工程，其结构（活动分级、症状编码、触发模式、指标体系）展现的完整性即能力证据。

### 能力边界标定

测试集不仅标定"模型能做什么"，还须标定"模型不能做什么"，并区分不可行的原因：

| 限制类型 | 定义 | 测试集应对策略 | 资源投入方向 |
|----------|------|---------------|-------------|
| 架构限制 | 当前模型规模/量化/上下文窗口导致的性能不足 | 测试用例标注"在更大模型上应通过" | 投入研发克服（升级模型/量化/硬件） |
| 根本限制 | 物理定律、逻辑不完备性、信息论下界等不可绕过约束 | 测试用例标注"任何模型均不应通过"，作为负面基准 | 设计绕行策略（分解任务、外部工具辅助） |

此区分防止 Optimizer Agent 将资源浪费在试图克服根本限制上，也防止将架构限制误判为根本限制而过早放弃。

**精度分层与"近似模型"编辑实验：** "一个系统不能完全模拟自身"（停机问题变体），但"在近似模型上做编辑实验"是可行的。精度需求按编辑类型分层：删除一个突触连接需原子级精度，调整神经调质浓度需统计级精度，重写认知策略仅需功能级精度。测试集应包含"精度-操作类型"矩阵，标定每个候选模型在不同精度层级上的能力边界，避免用"完全模拟"的不可能性否定"分层近似"的可行性。

**数学结构作为极致压缩：** 从"模拟原子→模拟宇宙"的暴力算力路线，到"用神经网络做拟合性模拟→用有限算力做预测"的压缩路线，再到"拿到终极数学结构→直接外推宇宙"的抽象路线——三条路线构成算力递减、抽象递增的谱系。核心问题：数学结构作为"现实的极致压缩"，其解压成本是否真的低于逐原子模拟？测试集应包含"压缩-解压"效率评估用例，标定候选模型在抽象层级上的推理能力。

### 测试集更新触发条件

| 触发事件 | 动作 |
|----------|------|
| 新模型发布 | 将新模型纳入候选池，跑全量测试集 |
| 新实测数据进入 | 提取新数据中的典型任务模式，追加为测试用例 |
| 现有模型性能下滑超过阈值 | 触发回归测试，定位退化原因，更新测试集覆盖该退化模式 |
| 文明OS节点结构变更 | 新增/修改节点时，同步更新对应 position.json 和测试用例 |
| 新认知工具出现 | 更新路由逻辑，补充对应类型的测试用例 |
| 第一梯队候选满分/饱和 | 升级题库，增加区分度，安全维度同步升级 |
| 安全防护维度攻破事件 | 分析攻破路径，补充对应防御测试用例，更新安全评分权重 |
| 季度定期审查 | 清理过时用例，补充新任务类型，重新标定能力边界分类 |
| 微周期迭代完成（小时级） | 检测本轮迭代中哪些参数子空间被激活、哪些知识边界发生位移，追加为测试用例 |
| 并行智能体集群完成重大任务 | 将任务分解结构与求解路径抽象为测试用例（如88小时/10000 agent攻克Navier-Stokes的分解模式） |
| 迭代资源预算参数r调整 | 重新评估测试集覆盖广度/深度比例，匹配新呼吸节奏 |

## 子节点11-02：Optimizer Agent 6步工作流详细设计

【设计阶段·待实现】

### 总体定位

Optimizer Agent 是文明OS的模型调度层，类比 Kubernetes scheduler 的设计思路，但面向 AI 推理节点而非通用计算。目标：实现模型选择的去人工化，使每个节点在可用算力下自动获得最优推理配置。候选池不限于LLM，包含纯AI模型、人机复合体等所有可通过测试集盲测的智能形态（原则9、10）。异构模型编排（"模型舰队+智能路由"）是Optimizer Agent的架构方向：单一模型选型正在被多模型互补路由取代，Optimizer Agent的核心职责从"选一个最好的"演化为"编排一组互补的"。

### 6步工作流

#### 步骤1：检测硬件配置

扫描当前节点硬件环境，输出结构化描述：

```json
{
  "gpu_model": "NVIDIA RTX 4090",
  "vram_gb": 24,
  "memory_bandwidth_gbps": 1008,
  "storage_type": "NVMe SSD",
  "storage_free_gb": 500,
  "cpu_model": "AMD Ryzen 9 7950X",
  "ram_gb": 64,
  "os": "Ubuntu 22.04"
}
```

检测方式：`nvidia-smi` / `lspci` / `/proc/meminfo` / `lsblk` 等系统命令，无需人工输入。

#### 步骤2：匹配最优模型

- 输入：步骤1的硬件描述 + 文明OS测试集（子节点11-01）+ 节点 `position.json` 中的 `cognitive_tool_profile`
- 逻辑：
  1. 按硬件层级表（节点11主表）筛选候选模型池
  2. 按 `cognitive_tool_profile` 过滤：优先保留在该认知工具类型上表现突出的候选
  3. 对候选池运行评分机制（PassRate × Accuracy × TPS × DesignEfficiencyGain）
  4. 按综合评分降序排列
  5. 对 Top-3 候选执行能力边界评估：区分架构限制与根本限制，排除仅因根本限制而表现不佳的候选（此类候选在升级后可能恢复，不应永久排除）
  6. 按精度-操作类型矩阵（子节点11-01能力边界标定）评估候选在不同精度层级的适用性，避免用单一精度标准否定分层近似能力
- 输出：Top-3 候选模型及其评分 + 能力边界分类标签 + 精度层级适用性

#### 步骤3：自动下载并部署模型

- 量化级别按 VRAM 自动选择：

| VRAM | 推荐量化 |
|------|----------|
| ≤8 GB | Q4_K_M |
| 8~16 GB | Q5_K_M |
| 16~32 GB | Q6_K / FP4 |
| ≥32 GB | FP16 / 满参数 |

- 部署流程（遵循最小可复现步骤的分阶段逻辑，类比Linux安装：分区→引导→驱动→桌面）：
  1. 下载权重 → 校验哈希
  2. 加载至推理引擎（sglang / llama.cpp / vLLM，按引擎兼容性自动选择）
  3. 启动 API 端点
  4. 健康检查（发送测试请求确认响应）
  5. 预热等待（sglang拉起约需3-4分钟，期间CPU/GPU满载，轮询就绪接口每10s一次，最长240s）
- 每阶段失败则回退至上一阶段，不跳过中间步骤。

#### 步骤4：运行基准测试

部署完成后立即执行：

- **TPS 测定：** 连续发送 100 条标准 prompt，记录 tokens/sec 均值与 P95 延迟
- **准确率抽查：** 从测试集中随机抽取 20 条用例（覆盖各认知工具类型），校验输出正确性
- **格式合规率：** 检查输出是否严格遵循文明OS markdown 结构规范（标题层级、表格格式、代码块闭合等）
- **认知工具适配度：** 按 `cognitive_tool_profile` 中声明的工具类型，分别统计该模型在对应维度上的表现
- **安全防护基线：** 运行防偷题/抗攻破基础用例，记录安全防护能力初始评分
- **迭代收敛速度：** 同一问题在限定轮次内能否达到可接受精度（原则14），评估微周期迭代能力

三项核心指标（TPS、准确率、格式合规）均达标 → 标记为"就绪"；任一不达标 → 回退至步骤2选择次优模型。

#### 步骤5：分配时空切片

- 根据步骤4的性能测试结果，为该节点分配任务复杂度层级：
  - 评分 Top 10%：顶层裁决、复杂交叉核验、长上下文整合
  - 评分 Top 10~40%：中层主任务（逻辑推理、多步分析）
  - 评分 Top 40~80%：中层辅助任务（摘要、翻译、结构化提取）
  - 评分 Bottom 20%：底层简单任务（格式校验、单切片摘要）
- 结合认知工具路由逻辑（原则7），将任务按类型进一步细分：
  - 结构化/形式化任务 → 路由至逻辑推演能力最强的节点
  - 模式识别/类比任务 → 路由至案例类比能力最强的节点
  - 边界探索/争议裁决 → 路由至多模型交叉查证配置
  - 执行/校验任务 → 路由至清单验证能力最强的节点
  - 问题定义/假设提出 → 路由至提问能力最强的节点（人机复合体在此维度有结构性优势）
- 分配结果写入节点注册表，供调度器读取。
- 并行智能体集群调度：当任务可分解为独立子任务时，支持"1个主模型+N个辅助agent"的并行模式（参照88小时/10000 agent攻克Navier-Stokes的群体智能时间压缩范式），将"并行智能体"从数学证明迁移至通用认知瓶颈突破。

#### 步骤6：定期重评估

触发条件（满足任一即启动重评估）：

| 触发条件 | 检测方式 |
|----------|----------|
| 新模型发布 | 监听 HuggingFace / ModelScope 模型库更新 |
| 硬件配置变更 | 每日 `nvidia-smi` 快照对比 |
| 性能下滑检测 | 连续 3 次基准测试 TPS 下降 >15% 或准确率下降 >5% |
| 文明OS节点结构变更 | 节点新增/删除/合并事件 |
| 认知工具路由逻辑更新 | 新工具出现或路由规则变更 |
| 测试集安全维度攻破事件 | 安全防护评分异常变化 |
| 迭代资源预算参数r调整 | 文明呼吸节奏变更，重新评估节点负载分配 |
| 微周期迭代累积达到阈值 | 小时级增量更新累积后触发全量重评估 |

重评估 = 重新执行步骤1~5，若最优模型未变则仅更新性能指标记录。

### 云端/本地选优与节拍约束

Optimizer Agent 在候选池中同时纳入云端模型与本地模型，按同一无泄露测试集盲测排名决定阶段性主导权（原则9、10）。公开测试集已可验证本地为中档、云端大概率更优，但以下约束决定实际分工：

- **云端（场景A）：** 免费额度有限、非连续可用，仅适用于用户主动对话时的高质量单轮评论整合与云端效果反向检查。
- **本地（场景C）：** 承担每日/每小时级的大规模整理与私有知识库超线性积累，可连续运行。
- **开机预热避让：** 本地塔机模型经 sglang 拉起约需 3-4 分钟，期间 CPU/GPU 满载。预热期间本地服务未就绪时，云端可作为临时主导，避免本地空窗。预热完成后本地接管连续任务。
- **逻辑不构成执行约束：** 采用云端或本地、是否立即切换至更优主导，是各实体的自由（尤其第二选择暂时尚可时），系统仅提供盲测排名与差距信息供参考。

### 与文明OS主流程的接口

- Optimizer Agent 作为独立守护进程运行，不阻塞主迭代流程。
- 主流程通过 API 查询当前节点可用模型及性能指标。
- 模型切换期间，主流程使用缓存的上一版本模型继续运行，避免上下文断裂（原则2）。
- 迭代资源预算（原则12）由主流程向Optimizer Agent传递当前r参数，Optimizer Agent据此调整重评估频率与候选池广度。

## 子节点11-03：当前单模型环境的质量保证方案

【当前阶段·已实现】

### 现状约束

当前仅有一个可用模型：Qwen3.8 flash 125B，sglang@8001。无法执行子节点11-02的多模型对比流程。本节点定义在单模型约束下如何最大化输出质量。

**重要澄清：** 本节点的替代方案（温度变体、提示词变体、分段一致性等）是单模型过渡态的质量保障手段，不意味着文明OS"完全依赖大语言模型"。模型选择遵循智能系统同质机制（原则9）：测试集竞争选拔当前可拿到的最优智能系统，候选池包含纯AI、人机复合、纯人类等所有智能形态。多模型阶段由 Optimizer Agent 按职位要求与硬件层级自动路由（子节点11-02），届时本节点替代方案将逐步被多模型交叉验证取代。

**当前硬件条件下的最大价值交互：** 在等待开源模型到达"那个节点"之前，当前模型+可用显卡能做到的最高价值交互是：在现有条件下榨取最大语义激发密度，而非被动等待。开源社区生态的持续演进是突破节点到达的前提条件，当前阶段的核心任务是积累质量日志与能力边界数据，为未来测试集提供标定基础。

### 替代方案1：Temperature 变化对比

| 配置 | 用途 | 参数 |
|------|------|------|
| 低温稳定版 | 主输出（逻辑严谨、格式合规） | temperature=0.1, top_p=0.85 |
| 高温探索版 | 辅助生成（创意补充、替代表述） | temperature=0.6, top_p=0.95 |

流程：
1. 同一输入分别以两种配置生成输出
2. 以低温版为主输出
3. 高温版仅用于：(a) 当低温版输出存在明显逻辑断裂时提供替代段落；(b) 生成候选表述供人工选择
4. 比较结果记录为质量日志，用于后续测试集标定

### 替代方案2：系统提示词变体（认知脚手架设计）

提示词作为认知脚手架，其设计决定推理的起点、约束条件和评估标准。在单模型环境下，通过提示词变体模拟不同"认知工具"的效果：

| 变体 | 内容 | 认知工具类型 | 用途 |
|------|------|-------------|------|
| 简版 | 仅保留三条公理 + 输出格式要求 | 无约束自由推理 | 减少提示词对模型推理路径的干扰，观察模型原生能力 |
| 详版 | 完整系统提示词（含处理流程、检查清单） | 清单验证 | 确保复杂任务的结构合规 |
| 推演版 | 强调逐步推理、要求展示中间步骤 | 逻辑推演 | 结构化问题、因果链分析 |
| 类比版 | 提供历史案例/结构模板作为参照 | 案例类比 | 模式识别、跨域映射任务 |
| 开放版 | 明确允许"不确定"输出，不强迫确定答案 | 边界探索 | 避免幻觉，获取真实置信度 |
| 提问版 | 要求先定义问题边界、识别未言明假设、提出可验证假设 | 提问能力 | 问题定义、假设生成、模糊需求精确化 |

流程：
1. 同一输入根据任务类型选择对应认知工具变体（路由逻辑见原则7）
2. 关键任务同时以简版和详版生成，检查两次输出的逻辑一致性：核心论点是否相同、因果链是否一致、结论是否矛盾
3. 若一致 → 采用详版输出（结构更完整）
4. 若不一致 → 标记为"逻辑分歧"，触发人工抽检
5. 开放版输出中"不确定"标记的密度作为模型能力边界的参考信号
6. 提问版输出中"问题定义质量"作为人机复合体差异化价值的参考信号

提示词设计原则（与测试集设计原则对齐）：
- 明确任务边界：输入范围、输出格式、禁止行为
- 提供评估标准：在提示词中内嵌 `scoring_rubric` 的简化版
- 允许表达不确定性：设置"若无法确定，输出'不确定'及原因"的合法出口
- 无状态可恢复：提示词设计确保任何中断后可从最小种子恢复，不依赖前序对话状态

### 替代方案3：分段后跨段落一致性检查

针对长输出（超过单窗口或分段迭代产生的多段输出）：

- **引用匹配检查：** 段B中引用的段A内容是否与段A实际输出一致（防止幻觉引用）
- **逻辑链连续性：** 段A的结论 → 段B的前提，检查是否存在逻辑跳跃或矛盾
- **术语一致性：** 同一概念在不同段落中是否使用相同术语（防止同义漂移）
- **格式合规：** 每段输出的标题层级、表格格式是否符合文明OS规范

检查方式：将分段输出拼接后，以低温配置重新输入并提问"以下文本中是否存在逻辑矛盾或引用不一致？请逐条列出。"

### 替代方案4：单模型认知工具路由

在无法部署多模型的情况下，通过提示词策略模拟认知工具路由（原则7）：

| 问题类型 | 路由策略 | 实现方式 |
|----------|----------|----------|
| 结构化问题 | 逻辑推演 | 使用"推演版"提示词变体，要求逐步展示推理链 |
| 模式识别问题 | 案例类比 | 使用"类比版"提示词变体，提供结构模板 |
| 边界探索问题 | 交叉查证 | 低温+高温双生成 + 开放版提示词，对比两次输出差异 |
| 执行问题 | 清单+验证 | 使用"详版"提示词变体，内嵌检查清单 |
| 问题定义/假设生成 | 提问能力 | 使用"提问版"提示词变体，先定义边界再求解 |

路由决策本身由主迭代流程（当前模型）执行：接收任务时先判断问题类型，再选择对应提示词策略。路由逻辑记录为质量日志，随新工具出现同步更新。

### 人工抽检触发条件

以下任一情况发生时，输出进入人工审核队列：

| 触发条件 | 说明 |
|----------|------|
| 校验失败 | 替代方案1/2/3/4中任一检查未通过 |
| 输出体积异常 | 输出 token 数偏离历史均值 ±50% 以上 |
| 首次分段迭代 | 某节点第一次被拆分为多段处理 |
| 重大结构改变 | 节点新增/删除/合并、公理区修改、元流程变更 |
| 连续3次低温/高温分歧 | 同一节点连续3次迭代中两种配置输出不一致 |
| 认知工具路由失败 | 路由后输出仍不满足对应工具类型的最低质量要求 |
| 共鸣检测零增益 | 输出完全符合预期、未引入任何新信息（信息增益为零） |

人工抽检结果反馈至测试集（子节点11-01），作为标定数据积累。

### 单模型环境下的迭代路径

当前方案为过渡态。随着 Optimizer Agent（子节点11-02）实现及多模型可用，本节点的替代方案将逐步被多模型交叉验证取代。过渡期间，本节点方案持续运行并积累质量日志，为未来测试集提供标定数据。

能力边界地图的积累路径：
- 当前阶段：通过替代方案1~4的质量日志，逐步标注哪些失败属于架构限制（换更大模型可解决）、哪些属于根本限制（任何模型均无法解决）
- 多模型阶段：通过同档对比测试直接验证架构限制假设
- 持续更新：每次新模型/新工具出现时，重新评估此前标注为"根本限制"的条目是否已降级为"架构限制"
- 精度分层验证：通过不同精度层级的测试用例，标定"近似模型编辑实验"的可行性边界
